# Linux Basics for Hackers
## Модуль 12 — Використання та зловживання сервісами

---

## Про що цей модуль

Сервіси — це програми, які працюють у фоновому режимі безперервно, чекаючи чогось: віддати веб-сторінку, прийняти SQL-запит, відповісти на SSH-з'єднання. Вони є робочою частиною сервера. Розуміння їх важливе як для налаштування власних інструментів, так і для того, щоб зрозуміти, що працює на цільовій машині і як туди потрапити.

---

## Що таке сервіс насправді

Сервіс (також відомий як демон) — це процес, який запускається під час завантаження і живе в фоновому режимі нескінченно довго. У нього немає вікна чи видимого інтерфейсу. Він просто сидить і слухає запити на певному мережевому порту, реагуючи, коли хтось до нього підключається.

Приклади:
- Apache слухає порт 80 (HTTP) та 443 (HTTPS) — віддає веб-сторінки
- SSH слухає порт 22 — приймає віддалені термінальні з'єднання
- MySQL слухає порт 3306 — відповідає на SQL-запити
- PostgreSQL слухає порт 5432 — те саме, але інша база даних

Номер порту — це те, що показує, який сервіс ти розмовляєш, коли підключаєшся до віддаленої машини. Це дуже важливо пізніше, коли ти будеш робити сканування портів через nmap: кожен відкритий порт — це сервіс, а кожен сервіс — це потенційний шлях всередину.

---

## Запуск та зупинка сервісів

Є два інструменти для керування сервісами: `service` (старий спосіб) і `systemctl` (сучасний стандарт). Обидва працюють у Kali. `systemctl` — те, що ти побачиш найчастіше в сучасних системах.

**За допомогою `service`:**

```bash
service apache2 start
service apache2 stop
service apache2 restart
service apache2 status
```

**За допомогою `systemctl`:**

```bash
systemctl start apache2
systemctl stop apache2
systemctl restart apache2
systemctl status apache2
```

Вони роблять одне й те саме. `systemctl` дає детальніший вивід про статус і є напрямком розвитку, тому варто вивчити обидва способи, але за замовчуванням використовувати `systemctl`.

**Увімкнути сервіс, щоб він запускатися автоматично під час завантаження:**

```bash
systemctl enable apache2
```

**Вимкнути автозапуск:**

```bash
systemctl disable apache2
```

## Apache — веб-сервер

Apache — один із найпоширеніших веб-серверів у світі. Запустивши його, ти перетворюєш машину на веб-сервер.

```bash
service apache2 start
```

Коли він запущений, відкрий браузер і перейди на `http://localhost`. Ти побачиш сторінку Apache за замовчуванням. Ця сторінка — просто файл у `/var/www/html/index.html`. Замінюй його своїм вмістом, і саме він буде віддаватися.

```bash
echo "<h1>My custom page</h1>" > /var/www/html/index.html
```

Онови сторінку — тепер віддається твій контент.

Apache веде журнал всього: кожен запит, кожен IP, що підключався, кожен запитаний файл. Ці логи знаходяться в `/var/log/apache2/`. Access log показує, хто підключався і що запитував. Error log показує, що зламалося.

**Чому це важливо для хакерства:** Apache мав безліч вразливостей протягом років. Неоновлений або погано налаштований Apache-сервер — поширений вхідний пункт. Коли ти скануєш ціль і бачиш відкриті 80 або 443 порти, майже напевно за цим стоїть Apache (або nginx, або інший веб-сервер). Версія має значення — старі версії мають відомі експлойти.

## SSH — віддалений доступ до терміналу

SSH (Secure Shell) дозволяє керувати терміналом іншого комп'ютера через мережу в зашифрованому вигляді. Це стандартний спосіб адміністрування віддалених Linux-систем.

```bash
ssh username@192.168.1.50
```

Це відкриває інтерактивну термінальну сесію на машині за цією IP, залогіненої як `username`. Усе, що ти вводиш, зашифровано в процесі передачі.

**Запуск SSH-сервісу на своїй машині** (щоб інші могли підключатися до тебе):

```bash
service ssh start
```

**Підключення через конкретний порт** (якщо сервер не на стандартному 22):

```bash
ssh -p 2222 username@192.168.1.50
```

**Копіювання файлів через SSH за допомогою `scp`:**

```bash
scp file.txt username@192.168.1.50:/home/username/
```

Це копіює `file.txt` на віддалену машину. Працює у обидві сторони — так само можна тягнути файли з віддаленої машини.

**Чому це важливо для хакерства:** SSH всюди. Якщо у тебе є дійсні облікові дані на машині з увімкненим SSH, ти маєш повний віддалений доступ до неї. Слабкі паролі на SSH-акаунтах — один із найпоширеніших способів компрометації серверів. Такі інструменти, як Hydra, можуть brute-force SSH-логін, якщо сервер не має rate limiting або fail2ban.

Kali постачається з паролем за замовчуванням для SSH-сервісу. Зміни його негайно, якщо вмикаєш його. Запуск Kali з паролями за замовчуванням і відкритим SSH — серйозна помилка.

## MySQL — база даних

MySQL — це сервер реляційних баз даних. Він зберігає дані в таблицях і відповідає на запити мовою SQL. Він стоїть за більшістю веб-додатків — системами логіну, користувацькими даними, товарами, і так далі.

**Запуск MySQL:**

```bash
service mysql start
```

**Вхід до MySQL shell:**

```bash
mysql -u root -p
```

`-u root` означає увійти як root користувач бази даних. `-p` означає запитати пароль. Коли ти всередині, з'являється промпт MySQL:

```sql
mysql>
```

Базовий SQL, який варто знати:

```sql
SHOW DATABASES;           -- показати всі бази даних
USE database_name;        -- переключитися на базу даних
SHOW TABLES;              -- показати таблиці в поточній базі
SELECT * FROM users;      -- вивести все з таблиці users
```

**Чому це важливо для хакерства:** SQL injection — одна з найпоширеніших веб-вразливостей. Якщо веб-додаток не санітизував вхідні дані, ти можеш вбудувати SQL-команди через форму логіну або URL і витягнути дані з бази. Навіть без SQL injection, знайти MySQL з слабким або типовим паролем root дає доступ до всього, що там зберігається — імена користувачів, хеші паролів, email, приватні дані.

---

## PostgreSQL

PostgreSQL — ще одна база даних, схожа на MySQL. Причина, чому вона варта згадки тут окремо, полягає в тому, що **Metasploit** — основний фреймворк для експлойтів, який ти будеш використовувати пізніше в цьому курсі — використовує PostgreSQL як бекенд для зберігання результатів сканування та даних сесій.

```bash
service postgresql start
```

Ти не будеш взаємодіяти з ним багато. Просто знай, що коли запускаєш Metasploit, він скаже, що база не підключена, якщо PostgreSQL ще не запущений.

## Перевіряємо, які сервіси працюють

Щоб побачити всі активні сервіси в системі:

```bash
systemctl list-units --type=service --state=running
```

Щоб побачити, які порти відкриті і що на них слухає:

```bash
ss -tlnp
```

Або старіший еквівалент:

```bash
netstat -tlnp
```

Вивід показує номер порту, протокол і конкретний процес, що слухає. Це корисно і для власної машини (щоб знати, що саме ти відкрив), і для цілі (якщо у тебе є доступ до машині і хочеш побачити, які сервіси працюють всередині).

## Паролі за замовчуванням — реальна проблема

Kali Linux постачається з паролями за замовчуванням для кількох сервісів. Так само і багато роутерів, камер, баз даних і серверів. "Admin/admin", "root/root", "admin/password" — це паролі, які ніколи не міняли після встановлення.

Велика частина реальних порушень відбувається саме так. Не через хитрі експлойти або нулі-дені — просто через те, що хтось спробував стандартний логін і пароль і зайшов.

Коли налаштовуєш будь-який сервіс, змінюй стандартні облікові дані негайно. Коли оцінюєш ціль, спроби стандартних логінів — один із перших кроків.

## Довідка по командам

| Команда | Що робить |
|---|---|
| `service name start/stop/restart` | Керування сервісом (старий синтаксис) |
| `systemctl start/stop/restart name` | Керування сервісом (сучасний синтаксис) |
| `systemctl status name` | Перевірити, чи працює сервіс |
| `systemctl enable name` | Запускати сервіс автоматично при завантаженні |
| `systemctl disable name` | Вимкнути автозапуск |
| `systemctl list-units --type=service` | Показати всі активні сервіси |
| `ssh user@ip` | Підключитися до віддаленої машини через SSH |
| `scp file user@ip:/path` | Скопіювати файл на віддалену машину |
| `mysql -u root -p` | Увійти в MySQL shell |
| `ss -tlnp` | Показати відкриті порти і слухаючі сервіси |

## Основні сервіси та їхні порти

| Сервіс | Порт за замовчуванням | Що робить |
|---|---|---|
| SSH | 22 | Віддалений термінал |
| HTTP (Apache) | 80 | Веб-сервер |
| HTTPS | 443 | Веб-сервер (шифрований) |
| MySQL | 3306 | База даних |
| PostgreSQL | 5432 | База даних |
| FTP | 21 | Передача файлів |
| SMTP | 25 | Відправка пошти |

Запам'ятати це варто. Коли nmap повертає список відкритих портів, знання, що зазвичай стоїть за кожним портом, дає тобі одразу уявлення, які сервіси перед тобою.

---

## Практика

- Запусти Apache через `service apache2 start`, потім відкрий браузер і перейди на `http://localhost`
- Замінити вміст `/var/www/html/index.html` на щось кастомне і оновити сторінку
- Запусти MySQL і увійди через `mysql -u root -p`, потім виконай `SHOW DATABASES;`
- Виконай `ss -tlnp` і подивись, які порти відкриті після запуску сервісів
- Зупини обидва сервіси, коли закінчиш — не лишай працювати те, що не треба
