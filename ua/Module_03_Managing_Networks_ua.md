# Linux Basics for Hackers
## Модуль 3 — Керування мережею

---

## Про що цей модуль

Хакерство майже завжди відбувається через мережу. Перш ніж ти зможеш зробити щось у мережі, тобі потрібно зрозуміти власну ідентичність у ній — IP-адресу, MAC-адресу — і як керувати обома. Цей модуль пояснює, як читати інформацію про мережу, змінювати її та розуміти основи роботи DNS.

---

## Дві адреси у кожного пристрою

Кожен пристрій у мережі має два ідентифікатори:

**IP-адреса** — це логічна адреса пристрою в мережі. Її призначає маршрутизатор (або ти сам вручну), і саме за нею дані знають, куди йти. Уяви це як вулицю та будинок — вона говорить мережі, де ти знаходишся, але може змінюватися.

**MAC-адреса** — це адреса, вбудована в фізичну мережеву карту виробником. Це ідентифікатор на рівні апаратного забезпечення, 12 шістнадцяткових символів, унікальний для кожного мережевого інтерфейсу у світі. Вона виглядає так: `00:1A:2B:3C:4D:5E`. На відміну від IP-адреси, її не можна назавжди змінити — але можна тимчасово підробити.

Розуміння обох важливе, бо в мережі саме вони ідентифікують тебе. Вміти читати й змінювати їх — базовий навик.

## Команди

### ifconfig

Це головний інструмент для читання та керування мережевими інтерфейсами. Запусти його без аргументів — і він покаже всю поточну конфігурацію мережі.

```bash
# 🐧 Debian/Kali (пакет net-tools)
ifconfig
```

> **⚡ CachyOS (Arch):** пакет `net-tools`, з якого йде `ifconfig`, там за замовчуванням **не встановлений** — Arch офіційно вважає його застарілим на користь пакета `iproute2` і команди `ip`. Аналог:
> ```bash
> ip addr show      # або скорочено: ip a
> ```

У виводі відображаються інтерфейси, які має твій пристрій. Найпоширеніші:

| Інтерфейс | Що це |
|---|---|
| `eth0` | Проводове Ethernet-підключення |
| `wlan0` | Бездротове (Wi‑Fi) підключення |
| `lo` | Loopback — система говорить сама з собою, завжди 127.0.0.1 |

У виводі шукай `inet` — це твоя поточна IP-адреса. Шукай `ether` — це твоя MAC-адреса.

Щоб побачити конкретний інтерфейс:

```bash
# 🐧 Debian/Kali
ifconfig eth0
```

> **⚡ CachyOS:** `ip addr show eth0`

Щоб призначити нову IP-адресу інтерфейсу:

```bash
# 🐧 Debian/Kali
ifconfig eth0 192.168.1.100
```

> **⚡ CachyOS:** `sudo ip addr add 192.168.1.100/24 dev eth0`

Щоб одночасно встановити маску підмережі:

```bash
# 🐧 Debian/Kali
ifconfig eth0 192.168.1.100 netmask 255.255.255.0
```

> **⚡ CachyOS:** у `ip` маска задається як префікс CIDR прямо в адресі — `/24` замість `255.255.255.0`, це і є той рядок вище (`192.168.1.100/24`).

Щоб увімкнути або вимкнути інтерфейс:

```bash
# 🐧 Debian/Kali
ifconfig eth0 up
ifconfig eth0 down
```

> **⚡ CachyOS:** `sudo ip link set eth0 up` / `sudo ip link set eth0 down`

Іноді потрібно вимкнути й знову увімкнути інтерфейс після внесення змін.

---

### iwconfig

Подібно до `ifconfig`, але спеціально для бездротових інтерфейсів. Показує інформацію про Wi‑Fi: назву мережі (ESSID), потужність сигналу та швидкість передачі.

```bash
# 🐧 Debian/Kali (пакет wireless-tools)
iwconfig
```

> **⚡ CachyOS (Arch):** `wireless-tools` так само вважається застарілим, замінник — `iw` (з пакета `iw`, той самий iproute2-стек, що й `ip`):
> ```bash
> iw dev                    # список бездротових інтерфейсів
> iw dev wlan0 link         # поточне підключення, сигнал, швидкість — аналог iwconfig
> iw dev wlan0 scan | less  # сканування мереж поблизу
> ```

Зазвичай ти просто читаєш з цього, а не записуєш. Але це корисно для того, щоб підтвердити, до якої бездротової мережі ти підключений і як виглядає сигнал.

---

### dhclient

Коли ти вручну задав IP-адресу через `ifconfig`, система більше не отримує її автоматично від маршрутизатора. Якщо хочеш повернутися до автоматичного IP від мережі, використовуй `dhclient`.

```bash
# 🐧 Debian/Kali
dhclient eth0
```

> **⚡ CachyOS (Arch):** `dhclient` (ISC DHCP client) вважається наприкінці свого життєвого циклу вгору за течією і не встановлюється за замовчуванням. Типовий інструмент на Arch/CachyOS — **`dhcpcd`**, або в більшості випадків DHCP взагалі керується автоматично через **NetworkManager**/**systemd-networkd**, тому вручну команду запускати майже ніколи не треба:
> ```bash
> sudo dhcpcd eth0          # разовий DHCP-запит через dhcpcd
> nmcli device connect eth0 # якщо мережею керує NetworkManager
> ```

Це надсилає запит серверу DHCP з фразою "дай мені IP-адресу", і він призначає її. Якщо ти вручну змінив IP і втратив інтернет, зазвичай це і виправляє проблему.

Також можна використовувати це для отримання нової IP-адреси, якщо вважаєш, що поточна викликає проблеми:

```bash
dhclient -r eth0     звільняє поточну IP-адресу
dhclient eth0        запитує нову
```

### Зміна MAC-адреси

MAC-адреси призначені для постійного використання, але їх легко підробити на рівні програмного забезпечення. Зміна триває лише до перезавантаження — після цього повертається справжня апаратна MAC-адреса.

Спочатку вимкни інтерфейс:

```bash
# 🐧 Debian/Kali
ifconfig eth0 down
```

Потім встанови нову MAC:

```bash
ifconfig eth0 hw ether 00:11:22:33:44:55
```

Потім увімкни його назад:

```bash
ifconfig eth0 up
```

> **⚡ CachyOS (Arch), той самий процес через `ip`:**
> ```bash
> sudo ip link set eth0 down
> sudo ip link set eth0 address 00:11:22:33:44:55
> sudo ip link set eth0 up
> ```

Запусти `ifconfig eth0`, щоб перевірити, чи зміна пройшла. Рядок `ether` тепер повинен показувати нову MAC-адресу.

> Зміна MAC-адреси існує тільки в пам'яті. Вона не зберігається після перезавантаження. Якщо потрібна постійна зміна, є інструменти на кшталт `macchanger`, які роблять це чистіше і працюють однаково на обох дистрибутивах (`apt-get install macchanger` / `pacman -S macchanger`).

### dig

`dig` служить для запитів до DNS — системи, яка переводить доменні імена типу `google.com` в IP-адреси. Він дає більше деталей, ніж просто ping до домену.

```bash
dig google.com
```

Розділ `ANSWER SECTION` у виводі показує IP-адреси, на які розв'язується `google.com`.

Щоб знайти записи поштових серверів:

```bash
dig google.com mx
```

`mx` означає Mail Exchange — це вказує, які сервери обробляють пошту для домену. Корисно для reconnaissance.

Інші типи записів, які варто знати:

| Тип запису | Що показує |
|---|---|
| `a` | IPv4-адреса домену |
| `aaaa` | IPv6-адреса |
| `mx` | Поштові сервери |
| `ns` | Сервери імен (які DNS-сервери є авторитетними) |
| `txt` | Текстові записи — часто містять перевірочні дані |

```bash
dig google.com ns
```

---

### DNS — коротка примітка про важливість

DNS (Domain Name System) — це адресна книга інтернету. Коли ти вводиш `google.com`, твій комп'ютер звертається до DNS-сервера: "яка IP-адреса для google.com?" і отримує відповідь. Без DNS тобі довелося б запам'ятовувати IP-адреси кожного сайту.

Хакери цікавляться DNS з кількох причин. По-перше, DNS-запити можуть багато розповісти про інфраструктуру цілі — поштові сервери, піддомени, сервери імен. По-друге, DNS можна маніпулювати — якщо ти зможеш перенаправити відповіді DNS, ти зможеш відправити людей на неправильний сервер повністю (це називається DNS poisoning або DNS spoofing, про що йдеться в наступних модулях).

Поки що достатньо знати, як використовувати `dig` для читання DNS-записів.

## Довідка по командам

| Завдання | 🐧 Debian/Kali | ⚡ CachyOS (Arch) / сучасний стандарт |
|---|---|---|
| Подивитися всі мережеві інтерфейси | `ifconfig` | `ip addr` (`ip a`) |
| Подивитися один інтерфейс | `ifconfig eth0` | `ip addr show eth0` |
| Встановити IP-адресу | `ifconfig eth0 192.168.1.100` | `ip addr add 192.168.1.100/24 dev eth0` |
| Вимкнути/увімкнути інтерфейс | `ifconfig eth0 down / up` | `ip link set eth0 down / up` |
| Подивитися бездротову інформацію | `iwconfig` | `iw dev wlan0 link` |
| Сканувати Wi-Fi мережі поблизу | `iwlist wlan0 scan` | `iw dev wlan0 scan` |
| Отримати IP від DHCP | `dhclient eth0` | `dhcpcd eth0` або `nmcli device connect eth0` |
| Випустити поточну IP | `dhclient -r eth0` | `dhcpcd -k eth0` |
| Подивитися таблицю маршрутизації | `route -n` | `ip route` |
| Підробити MAC-адресу | `ifconfig eth0 hw ether 00:11:22:33:44:55` | `ip link set eth0 address 00:11:22:33:44:55` |
| DNS-запит | `dig google.com` | `dig google.com` (однаково на обох) |
| Знайти поштові сервери | `dig google.com mx` | `dig google.com mx` |

## Практика

- Запусти `ifconfig` (або `ip addr`, якщо ти на CachyOS) і знайди IP-адресу та MAC-адресу для `eth0` або `wlan0`
- Запусти `dig google.com` і прочитай секцію answer — зверни увагу на повернуті IP-адреси
- Запусти `dig google.com mx` і подивись, які сервери обробляють пошту Google
- Спробуй змінити свою IP на `192.168.1.100`, підтверди це через `ifconfig`/`ip addr`, а потім запусти `dhclient eth0`/`dhcpcd eth0`, щоб отримати свіжу IP від DHCP

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

Це один із розділів курсу, де матеріал не просто "інший на іншому дистрибутиві" — він реально застарів технічно, і це варто розуміти на рівні теорії, а не тільки запам'ятати нові команди.

**Чому `ifconfig`/`iwconfig`/`route`/`netstat` (пакет `net-tools`) вважаються legacy:**

`net-tools` було написано в 1990-х під ядра Linux, які спілкувалися з мережевим стеком через застарілий інтерфейс `ioctl()`. У 2001 році в ядро додали підсистему **Netlink** — сучасний, розширюваний, асинхронний протокол для комунікації user-space ↔ kernel, який значно краще підтримує IPv6, VLAN, tunnels, multiple routing tables і сучасні мережеві простори імен (network namespaces, критичні для контейнерів/Docker/Kubernetes). Пакет **`iproute2`** (команди `ip`, `ss`, `tc`, `bridge`) написаний саме поверх Netlink — тому він і швидший, і функціонально ширший, і єдиний, що коректно показує сучасні мережеві конструкції (наприклад, кілька IP-адрес на одному інтерфейсі, policy routing, VXLAN).

Debian й Kali досі встановлюють `net-tools` за замовчуванням із міркувань зворотної сумісності та звички (величезна кількість застарілих скриптів і туторіалів написані під `ifconfig`), але офіційна документація ядра прямо каже: net-tools deprecated. Arch і CachyOS цю спадщину відкинули повністю — `net-tools` навіть немає в базовій установці.

**Ключова відмінність у мисленні, яку варто засвоїти:**

| | `ifconfig`/net-tools | `ip`/iproute2 |
|---|---|---|
| Модель адреси | 1 інтерфейс = 1 основна IP (додаткові — через `:0` аліаси, незручно) | Довільна кількість адрес на інтерфейсі — нативно |
| IPv6 | Обмежена/незручна підтримка | Повноцінна підтримка з самого початку |
| Мережеві простори імен (namespaces) | Не підтримує | `ip netns` — базова функція, критична для Docker/K8s |
| Синтаксис | Історично складений, непослідовний | Єдина логічна граматика: `ip OBJECT COMMAND` (`ip addr add`, `ip link set`, `ip route add`) |
| Джерело даних | ioctl (старий, обмежений) | Netlink sockets (сучасний, розширюваний) |

**Практичний висновок для будь-якого дистрибутива, не тільки CachyOS:** якщо ти вчишся мережам у 2024+, вклади час саме в `ip`/`ss`/`iw`, а не в `ifconfig`/`netstat`/`iwconfig`. Ці інструменти показані в курсі як історична база (і ти реально зустрінеш `ifconfig` на старих серверах і в застарілих write-up'ах), але production-навички системного інженера сьогодні будуються на iproute2-стеку. Приклад типового "сучасного" сеансу діагностики мережі:

```bash
ip -c a                       # кольоровий вивід всіх адрес
ip -c r                       # таблиця маршрутизації
ss -tulnp                     # відкриті порти + процеси (сучасний netstat)
iw dev wlan0 link             # стан Wi-Fi підключення
resolvectl status             # стан DNS-резолвера (де використовується systemd-resolved)
```

Це той самий набір даних, який давали старі команди, але через єдиний, узгоджений, підтримуваний ядром API.
