# Linux Basics for Hackers
## Модуль 14 — Бездротові мережі

---

## Про що цей модуль

Wi-Fi — одна з найпоширеніших поверхонь атаки в реальному світі, бо вона практично скрізь і часто налаштована погано. Цей модуль пояснює, як бездротові мережі працюють насправді, які інструменти використовуються для їх перевірки та аудиту, і як Bluetooth вписується в цю картину. Усе тут слід використовувати тільки на мережах і пристроях, які ти власник або маєш письмовий дозвіл їх тестувати.

---

## Як Wi-Fi працює насправді (та частина, яка важлива для нас)

Коли твій ноутбук підключається до роутера, він обмінюється радіосигналами на певній частоті. Зазвичай Wi-Fi карта звертає увагу лише на пакети, адресовані їй — вона ігнорує все інше, що плаває в повітрі. Це називається **managed mode**.

Щоб робити серйозний бездротовий аналіз, потрібно, щоб карта слухала все — всі пакети від усіх пристроїв на всіх мережах у радіусі, а не лише ті, що призначені тобі. Це називається **monitor mode**. Це як перейти від приватної розмови до того, щоб чути все в кімнаті.

Не кожен Wi-Fi адаптер підтримує monitor mode або packet injection. Вбудована карта більшості ноутбуків — ні. Потрібен зовнішній USB-адаптер, який спеціально підтримує ці функції — Alfa AWUS036ACH або схожі адаптери є стандартним вибором для такого типу роботи.

## Набір інструментів для бездротових мереж — `aircrack-ng`

`aircrack-ng` — це набір інструментів, не одна програма. Основні, які будеш використовувати:

| Інструмент | Що робить |
|---|---|
| `airmon-ng` | Вмикає та вимикає monitor mode на адаптері |
| `airodump-ng` | Захоплює пакети і показує всі мережі поблизу |
| `aireplay-ng` | Впроваджує пакети в мережу (для примусового перепідключення тощо) |
| `aircrack-ng` | Спробує зламати захоплений WPA-хендшейк |

Вони працюють разом як конвеєр. Ти рідко використовуєш лише один.

---

## Включаємо monitor mode на карті

Спочатку знайди назву бездротового інтерфейсу:

```bash
iwconfig
```

Вивід показує інтерфейси. Зазвичай це `wlan0` або щось подібне.

Перш ніж увімкнути monitor mode, вбий будь-які процеси, які можуть заважати:

```bash
airmon-ng check kill
```

Це зупиняє NetworkManager та інші фонові інструменти, які намагаються керувати інтерфейсом. Якщо цей крок пропустити, monitor mode часто ламається або інтерфейс продовжує відвалюватися.

Тепер увімкни monitor mode:

```bash
airmon-ng start wlan0
```

Імовірно, інтерфейс буде перейменований у `wlan0mon`, щоб позначити, що він тепер у monitor mode. Перевір ще раз через `iwconfig`.

Щоб повернутися до звичайного managed mode:

```bash
airmon-ng stop wlan0mon
```

## Сканування сусідніх мереж через `airodump-ng`

Коли карта у monitor mode, можна захоплювати все, що в повітрі:

```bash
airodump-ng wlan0mon
```

Вивід показує всі мережі в радіусі:

```
BSSID              PWR  Beacons  #Data  CH   MB   ENC   ESSID
AA:BB:CC:DD:EE:FF  -45      120     34   6  130   WPA2  HomeNetwork
11:22:33:44:55:66  -72       80     12  11   54   WPA2  CoffeeShop_WiFi
```

Розберемо колонки:

| Колонка | Що означає |
|---|---|
| BSSID | MAC-адреса роутера |
| PWR | Сила сигналу — більш негативне = слабше |
| CH | Канал, на якому ведеться передача |
| ENC | Тип шифрування (WPA2, WPA3, WEP, OPN) |
| ESSID | Назва мережі (SSID), яку бачиш при підключенні |

Щоб зосередитися на конкретній мережі і також побачити підключених клієнтів:

```bash
airodump-ng --bssid AA:BB:CC:DD:EE:FF --channel 6 -w capture wlan0mon
```

- `--bssid` фільтрує до одного конкретного роутера
- `--channel` фіксує один канал, щоб не пропустити пакети під час гойдання по каналах
- `-w capture` записує все захоплене в файли, що починаються з "capture"

## Термінологія Wi‑Fi, яку варто знати

**SSID** — назва мережі. Те, що ти бачиш у списку під час підключення.

**BSSID** — MAC-адреса роутера. На відміну від SSID (який власник може налаштувати як завгодно), BSSID прив'язаний до обладнання.

**Channel** — Wi-Fi працює на конкретних каналах в діапазонах 2.4GHz або 5GHz. 2.4GHz має канали 1–14 (1, 6 і 11 — стандартні непересічні канали). 5GHz має набагато більше каналів.

**WPA2** — поточний стандарт шифрування Wi‑Fi. Використовує AES. Замінив WEP (який був повністю зламаний) і WPA. WPA3 — новіший стандарт, який з'являється на сучасних роутерах.

**WEP** — старий і повністю зламаний. Мережа з WEP може бути зламана за лічені хвилини. Якщо коли-небудь побачиш таку мережу в дикій природі, це, швидше за все, застарілий пристрій, який давно не оновлювався.

**Handshake** — коли пристрій підключається до WPA2-мережі, роутер і пристрій обмінюються 4-way handshake, щоб перевірити пароль. Захоплення цього handshake — це те, на чому базується злам WPA2: ти перехоплюєш його, а потім злам в офлайн режимі.

## Сканування через `iwlist`

Якщо хочеш просто побачити сусідні мережі без переходу в monitor mode:

```bash
iwlist wlan0 scan
```

Це дає базове сканування видимих мереж — SSID, BSSID, канал, сила сигналу, тип шифрування. Менш детально, ніж airodump-ng, але не потребує monitor mode і нормально працює для recon без торкання чогось.

## Bluetooth з BlueZ

Bluetooth — коротший бездротовий протокол, який використовується телефонами, навушниками, клавіатурами, динаміками, смарт-годинниками та десятками інших пристроїв. Інструменти для роботи з Bluetooth у Linux поставляються з пакету **BlueZ**.

**Сканування сусідніх Bluetooth-пристроїв:**

```bash
hcitool scan
```

Вивід:
```
Scanning...
    AA:BB:CC:DD:EE:FF    John's iPhone
    11:22:33:44:55:66    Sony WH-1000XM4
```

Це показує будь-які пристрої, які в discoverable mode. Пристрій у discoverable mode активніше рекламує свою присутність — так ви пари нові пристрої. Багато людей залишають свої пристрої постійно discoverable, навіть не усвідомлюючи цього.

**Перевірка, чи пристрій доступний:**

```bash
l2ping AA:BB:CC:DD:EE:FF
```

Це пінгує Bluetooth-пристрій так само, як `ping` пінгує IP-адресу — підтверджує, що пристрій в радіусі і відповідає.

**Отримання інформації про пристрій:**

```bash
hcitool info AA:BB:CC:DD:EE:FF
```

Повертає назву пристрою, виробника, підтримувані функції та інші метадані.

**Сканування з більшою деталізацією:**

```bash
hcitool lescan
```

`lescan` — для **Bluetooth Low Energy (BLE)** пристроїв — фітнес-трекерів, датчиків розумного дому, IoT-пристроїв. Вони часто транслюють безперервно і є зростаючою поверхнею атаки.

## На що дивитися під час бездротового recon

Коли ти робиш бездротове reconnaissance на мережі, якою маєш право користуватися, ось що важливо:

- **Open networks (OPN)** — без шифрування, усе передається відкрито
- **WEP-мережі** — зламане шифрування, зламується за лічені хвилини
- **WPA2-мережі зі слабкими паролями** — захоплюється handshake, зламується офлайн за допомогою wordlists
- **Hidden SSIDs** — мережі, які не транслюють назву; в `airodump-ng` вони показуються як порожні ESSID, але BSSID все ще є
- **Bluetooth-пристрої в discoverable mode** — особливо пристрої, які не повинні бути discoverable (клавіатури, корпоративні ноутбуки)

## Довідка по командам

| Команда | Що робить |
|---|---|
| `iwconfig` | Показати бездротові інтерфейси та їх поточний режим |
| `iwlist wlan0 scan` | Сканувати сусідні Wi‑Fi-мережі |
| `airmon-ng check kill` | Вбити процеси, які заважають monitor mode |
| `airmon-ng start wlan0` | Увімкнути monitor mode |

| `hcitool scan` | Сканувати discoverable Bluetooth-пристрої |
| `hcitool lescan` | Сканувати BLE-пристрої |
| `l2ping [MAC]` | Пінгнути Bluetooth-пристрій |
| `hcitool info [MAC]` | Отримати деталі про Bluetooth-пристрій |

## Практика

- Виконай `iwlist wlan0 scan` і подивися на вивід — знайди свою домашню мережу, відміть канал і тип шифрування
- Виконай `hcitool scan` у кімнаті і подивись, які Bluetooth-пристрої з'являться — перевір, скільки з них у discoverable mode
- Якщо є сумісний адаптер: переведи його в monitor mode через `airmon-ng`, запусти `airodump-ng` на 30 секунд, знайди свій роутер у виводі, відзнач канал і BSSID, потім зупини захоплення і виведи карту з monitor mode

Роби практику з `airodump-ng` тільки в своїй домашній мережі. Захоплення трафіку в мережах, якими ти не володієш, є незаконним у більшості країн незалежно від того, що ти потім робиш з даними.

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

Робочий процес "airodump-ng захоплює handshake → перекидаємо в John the Ripper/aircrack-ng для offline brute-force" описаний у модулі, все ще працює, але за останні роки з'явилися суттєво важливі зміни, про які варто знати теоретично, навіть якщо конкретні команди не входять у цей курс:

**1. PMKID-атака (hcxdumptool + hashcat) — не потребує чекати на клієнта.** Класичний handshake-захоплення вимагає або чекати, поки клієнт підключиться, або примусово деавтентифікувати вже підключеного клієнта (`aireplay-ng --deauth`), що само по собі помітно в мережевому моніторингу. У 2018 році дослідник Jens Steube (автор hashcat) показав, що багато точок доступу передають **PMKID** (Pairwise Master Key Identifier) в самому першому EAPOL-фреймі одразу після запиту асоціації — тобто зловити достатньо даних для offline-атаки можна взагалі без активних клієнтів і без deauth-пакетів:
```bash
hcxdumptool -i wlan0mon -o capture.pcapng --enable_status=1
hcxpcapngtool capture.pcapng -o hashes.hc22000
hashcat -m 22000 hashes.hc22000 wordlist.txt
```
Це тихіший і швидший метод, ніж класична пара airodump-ng+aireplay-ng, і сьогодні є практичним стандартом для аудиту WPA2-мереж.

**2. WPA3/SAE ламає стару модель атаки повністю.** WPA2 вразливий до offline brute-force саме тому, що весь чотиристоронній handshake можна перехопити пасивно, а потім перебирати паролі офлайн скільки завгодно часу без взаємодії з точкою доступу. **WPA3** використовує протокол **SAE** (Simultaneous Authentication of Equals, він же Dragonfly Handshake) замість PSK-обміну WPA2 — ключова властивість SAE — **forward secrecy** і стійкість до офлайн-словникових атак у принципі: перехоплений трафік не дає матеріалу для офлайн-брутфорсу, кожна спроба автентифікації вимагає живої взаємодії з точкою доступу, що дозволяє їй виявляти й обмежувати масові спроби (rate limiting). Це не "патч", а зміна математичної моделі атаки: старий підхід aircrack-ng/hashcat на WPA3-SAE мережах просто не працює так само, як на WPA2.

**Практичний висновок:** якщо ціль на WPA2 — PMKID-метод через `hcxdumptool`+`hashcat` сьогодні ефективніший і непомітніший за класичний deauth+handshake підхід з цього модуля. Якщо ціль на WPA3 — потрібна принципово інша модель атаки (найчастіше фокус зміщується на даунгрейд-атаки, якщо мережа підтримує "перехідний режим" WPA2/WPA3 одночасно, або на слабкості реалізації, а не на офлайн-брутфорс паролю).
