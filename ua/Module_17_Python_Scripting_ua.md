## Чому Python для роботи в безпеці

Python вже давно є домінуючою мовою в безпеці та хакерстві. Причини прості:

- Синтаксис чистий і читабельний — ти швидко розумієш, що робить скрипт
- Стандартна бібліотека охоплює мережу, роботу з файлами, криптографію і багато іншого без встановлення чогось додатково
- Існує тисячі сторонніх бібліотек для задач безпеки
- Більшість експлойтів, інструментів і proof-of-concept-коду, які ти знайдеш в інтернеті, написані на Python
- Він працює в будь-якій Linux-системі

Можливість читати Python реально корисна ще до того, як ти почнеш писати власні інструменти. Більшість експлойтів, з якими ти зіткнешся, — це Python-скрипти. Якщо ти їх не можеш читати, ти працюєш в сліпу.

## Python 2 vs Python 3

Python 2 мертвий — офіційно припинив підтримку в 2020 році. Усе, що ти пишеш, має бути на Python 3. Kali постачається з Python 3 за замовчуванням. Коли ти бачиш старі туторіали з `print "hello"` без дужок, це Python 2 синтаксис. У Python 3 це `print("hello")`.

Перевір свою версію:

```bash
python3 --version
```

Запусти інтерпретатор Python 3:

```bash
python3
```

Це кидає тебе в інтерактивну оболонку, де можна вводити Python напряму. Це добре для перевірки дрібних речей. Вийти — `exit()` або `Ctrl+D`.

## Твій перший скрипт

Створи файл `hello.py`:

```python
#!/usr/bin/env python3

print("Hello, world")
```

Рядок shebang трохи інший, ніж у Bash — `/usr/bin/env python3` знаходить інтерпретатор Python 3 де б він не був в системі, що більш портативно, ніж жорстко зашивати шлях.

Запусти його:

```bash
python3 hello.py
```

Або зроби виконуваним і запусти напряму:

```bash
chmod 755 hello.py
./hello.py
```

## Змінні та типи даних

Python динамічно типізований — ти не оголошуєш типи, ти просто присвоюєш значення, а Python сам здогадується.

```python
name = "Alice"           # string
port = 80                # integer
pi = 3.14                # float
active = True            # boolean
```

**Strings** — текст, завжди в лапках:

```python
target = "192.168.1.1"
print("Scanning: " + target)
print(f"Scanning: {target}")    # f-string, більш чистий спосіб вставляти змінні
```

**Integers** — цілі числа, використовуються для портів, лічильників, індексів:

```python
port = 22
print(port + 1)    # 23
```

**Lists** — впорядковані колекції, як масиви:

```python
ports = [22, 80, 443, 3306]
print(ports[0])      # 22 — індексація починається з 0
print(ports[-1])     # 3306 — від'ємний індекс рахуватиме з кінця
```

**Dictionaries** — пари key-value, як таблиця пошуку:

```python
user = {"username": "admin", "password": "password123", "role": "root"}
print(user["username"])    # admin
```

Dictionaries дуже поширені в security-скриптах — ти побачиш їх використання для зберігання розібраних даних, HTTP-заголовків, конфігурацій тощо.

## Отримання введення від користувача

```python
target = input("Enter target IP: ")
print("Scanning " + target)
```

`input()` зупиняє виконання і чекає, потім зберігає те, що ввів користувач, у вигляді рядка. Якщо треба число:

```python
port = int(input("Enter port: "))
```

`int()` конвертує рядок у ціле число. Без цього перетворення `"80" + 1` викине помилку — Python не змішує типи мовчки.

## Умовні конструкції

```python
password = input("Enter password: ")

if password == "secretpass":
    print("Access granted")
elif password == "admin":
    print("Admin access")
else:
    print("Wrong password")
```

Python використовує відступи для визначення блоків коду — без фігурних дужок. Стандарт — 4 пробіли. Якщо відступи несумісні, Python викине помилку. Це те, що заганяє в тупик майже кожного початківця, який приходить з іншої мови.

Поширені оператори порівняння:

| Оператор | Значення |
|---|---|
| `==` | Дорівнює |
| `!=` | Не дорівнює |
| `>` `<` | Більше / менше |
| `>=` `<=` | Більше або дорівнює / менше або дорівнює |
| `in` | Перевіряє, чи значення є в списку або рядку |

## Цикли

**For loop** — перебір списку або діапазону:

```python
ports = [22, 80, 443]
for port in ports:
    print(f"Checking port {port}")
```

```python
for i in range(1, 256):
    print(f"192.168.1.{i}")
```

`range(1, 256)` генерує числа від 1 до 255. Так ти можеш побудувати базовий діапазон IP для сканування.

**While loop** — повторювати, поки умова істинна:

```python
attempts = 0
while attempts < 3:
    password = input("Password: ")
    if password == "secret":
        print("Access granted")
        break
    attempts += 1
print("Too many attempts")
```

`break` негайно вийде з циклу. `continue` перейде до наступної ітерації.

## Функції

Функції дозволяють написати блок коду один раз і викликати його за ім'ям, коли треба:

```python
def scan_port(ip, port):
    print(f"Scanning {ip}:{port}")

scan_port("192.168.1.1", 80)
scan_port("192.168.1.1", 443)
```

Функції можуть повертати значення:

```python
def add(a, b):
    return a + b

result = add(3, 4)
print(result)    # 7
```

Добре структуровані скрипти кладуть логіку в функції і викликають їх знизу файлу. Це робить код читабельнішим і повторно використовуваним.

## Імпорт бібліотек

Реальна сила Python — у його бібліотеках. Ти підключаєш їх через `import`:

```python
import socket
import os
import sys
```

**socket** — для мережевих з'єднань, основи мережевих інструментів:

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("google.com", 80))
print("Connected")
s.close()
```

Це відкриває TCP-з'єднання з google.com на 80 порту — те саме, що браузер робить при відвідуванні сайту через HTTP.

**os** — для взаємодії з операційною системою:

```python
import os

os.system("ls -la")           # запуск командної оболонки
cwd = os.getcwd()             # поточна директорія
files = os.listdir(".")      # список файлів у поточній директорії
```

**sys** — для системних речей, наприклад параметрів командного рядка:

```python
import sys

print(sys.argv)               # список аргументів, переданих скрипту
```

```python
# python3 script.py 192.168.1.1 80
# sys.argv = ['script.py', '192.168.1.1', '80']
```

Це дозволяє передавати аргументи в скрипт під час запуску, замість того, щоб жорстко зашивати значення.

## Встановлення сторонніх бібліотек

Стандартна бібліотека охоплює багато, але у Python-екосистемі сотні тисяч сторонніх пакетів для спеціалізованих задач:

```bash
pip3 install requests
pip3 install scapy
pip3 install paramiko
```

- `requests` — чистіші HTTP-запити, ніж використовувати `socket` напряму
- `scapy` — потужне створення й аналіз пакетів
- `paramiko` — SSH-з'єднання в Python

Імпорт після встановлення:

```python
import requests

response = requests.get("http://example.com")
print(response.status_code)
print(response.text)
```

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

**Пряме `pip3 install` у системний Python сьогодні часто взагалі заборонено.** Починаючи з Debian 12/Kali 2023+ і на будь-якому актуальному Arch/CachyOS, спроба виконати `pip3 install requests` без додаткових прапорів видасть помилку:

```
error: externally-managed-environment
```

Це не баг, а свідоме рішення (PEP 668): дистрибутиви керують системними Python-пакетами через `apt`/`pacman`, і якщо `pip` тихо перезапише системний пакет своєю версією, це може зламати інші програми, які покладаються на конкретну версію бібліотеки в системі. Правильний сучасний підхід — **віртуальні середовища (`venv`)**, ізольована копія Python з власним набором пакетів для кожного проєкту:

```bash
python3 -m venv myproject-env      # створити віртуальне середовище в папці myproject-env
source myproject-env/bin/activate  # активувати (промпт термінала зміниться)
pip install requests scapy paramiko   # тепер встановлюється тільки в це середовище, без конфліктів
deactivate                          # вийти з середовища, коли закінчив
```

Кожен проєкт отримує власний ізольований набір версій бібліотек — не буде ситуації, коли оновлення однієї бібліотеки для одного скрипта ламає інший.

**Для CLI-утиліт, написаних на Python (не для власних скриптів, а для готових інструментів з PyPI)** — сучасний стандарт **`pipx`**, який автоматично створює окреме venv для кожної утиліти, але робить її доступною глобально як звичайну команду в `$PATH`:

```bash
# 🐧 Debian/Kali
sudo apt install pipx

# ⚡ CachyOS (Arch)
sudo pacman -S python-pipx

pipx install httpie      # встановлює інструмент httpie, ізольовано, але команда httpie доступна всюди
```

**Практичний висновок:** для швидкого одноразового скрипта в межах курсу `pip3 install --user` (додавши `--user`, щоб не чіпати системні пакети) все ще працює як найшвидший шлях. Але для будь-якого реального проєкту чи інструмента, яким плануєш користуватися довго, — `venv` для власного коду і `pipx` для готових CLI-утиліт є практичним стандартом сьогодні, і саме тому нові дистрибутиви блокують "голий" `pip install` в системний Python за замовчуванням.

## Практичний приклад — базовий port scanner

Це зводить разом більшість того, що було вище, в щось реально корисне:

```python
#!/usr/bin/env python3
import socket
import sys

def scan_port(ip, port):
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.settimeout(1)
    result = s.connect_ex((ip, port))   # повертає 0, якщо з'єднання успішне
    s.close()
    return result == 0

target = input("Enter target IP: ")
print(f"
Scanning {target}...
")

for port in range(1, 1025):
    if scan_port(target, port):
        print(f"Port {port} is OPEN")

print("
Scan complete.")
```

`connect_ex` намагається підключитися і повертає код помилки замість того, щоб кидати виняток — 0 означає успіх (порт відкритий). `settimeout(1)` означає, що не чекати більше 1 секунди на порт перед переходом до наступного.

Це спрощена версія того, що робить nmap. Розуміння цього робить вивід nmap набагато зрозумілішим.

## Обробка помилок

Речі йдуть не так. Мережеві з'єднання падають, файлів не існує, користувач вводить неправильне. Python використовує `try/except` для коректної обробки помилок:

```python
try:
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.connect(("192.168.1.1", 80))
    print("Connected")
except socket.error as e:
    print(f"Connection failed: {e}")
finally:
    s.close()
```

`try` — спробувати це
`except` — якщо це зламалося, виконати замість цього
`finally` — виконати незалежно від всього (тут розташовується очищення)

Без обробки помилок один збій з'єднання зламає весь скрипт. З нею скрипт продовжує роботу і говорить, що саме пішло не так.
