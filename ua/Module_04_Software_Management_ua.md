# Linux Basics for Hackers
## Модуль 4 — Керування програмним забезпеченням

---

## Про що цей модуль

Kali поставляється з готовими інструментами, але ти постійно будеш додавати нові, оновлювати існуючі або завантажувати щось напряму з GitHub розробника. Цей модуль пояснює, як Linux керує встановленням програм — це зовсім не схоже на Windows — і як отримувати інструменти, яких немає в стандартній бібліотеці.

---

## Як Linux керує програмним забезпеченням

У Windows ти завантажуєш інсталятор з сайту, двічі клацаєш і проходиш майстер встановлення. Linux працює інакше.

Linux використовує **репозиторії** — величезні онлайн-бібліотеки програмного забезпечення, які підтримуються та перевіряються дистрибутивом. Замість пошуку посилання для завантаження ти просто говориш системі назву того, що хочеш, і вона знаходить, завантажує та встановлює це автоматично, включно з усіма бібліотеками, які потрібні для роботи.

Інструмент, який керує всім цим у Kali (і системах на базі Debian), — це `apt-get`.

> **🐧 Debian/Kali vs ⚡ CachyOS:** Kali та Debian використовують формат пакетів `.deb` і менеджер `apt`. CachyOS побудований на Arch Linux і використовує зовсім інший формат пакетів (`.pkg.tar.zst`) та менеджер **`pacman`**. Це не "той самий інструмент з іншою назвою" — інша модель репозиторіїв (rolling release замість стабільних релізів), інша структура залежностей, інший підхід до конфігурації. Нижче в кожному розділі буде показано аналог для CachyOS/Arch поруч із командою Debian.

Список репозиторіїв, які знає твоя система, знаходиться у файлі `sources.list` за шляхом `/etc/apt/sources.list`. Зазвичай цей файл краще не чіпати, якщо ти не знаєш, що додаєш — неофіційні репозиторії можуть містити зловмисні пакети.

На CachyOS/Arch аналогічний список репозиторіїв знаходиться в `/etc/pacman.conf`, а дзеркала (сервери завантаження) — в `/etc/pacman.d/mirrorlist`.

## Команди

### apt-get update

Перш ніж щось встановлювати, виконай цю команду. Вона ніщо не встановлює й не оновлює — вона просто оновлює локальний список того, що доступно в репозиторіях. Якщо пропустити її і спробувати встановити щось, можна отримати застарілу версію або помилку.

```bash
# 🐧 Debian/Kali
apt-get update
```

Постарайся робити це перед кожним встановленням.

> **⚡ CachyOS (Arch):** окремої команди "тільки оновити список" немає — синхронізація бази і власне оновлення системи зазвичай відбуваються разом:
> ```bash
> sudo pacman -Sy      # тільки синхронізувати базу пакетів (аналог apt-get update)
> sudo pacman -Syu     # синхронізувати базу і одразу оновити всі пакети (рекомендований спосіб)
> ```
> **Важливо:** на Arch-подібних дистрибутивах ніколи не роби "часткове оновлення" (`pacman -Sy` окремо, а потім встановлення нового пакета пізніше без повного `-Syu`) — це офіційно визнана причина поламаних систем, бо залежності між пакетами в репозиторії синхронізовані тільки в момент повного `-Syu`.

---

### apt-get install

Завантажує та встановлює пакет. Kali автоматично обробляє залежності — якщо інструмент потребує ще п'ять бібліотек для роботи, він їх також отримає.

```bash
# 🐧 Debian/Kali
apt-get install wireshark
```

Перед завантаженням система попросить підтвердження. Введи `y` і натисни Enter.

Щоб пропустити запит підтвердження:

```bash
apt-get install -y wireshark
```

Прапорець `-y` автоматично відповідає "так". Корисно, коли ти знаєш, що робиш.

> **⚡ CachyOS (Arch):**
> ```bash
> sudo pacman -S wireshark-qt      # встановити пакет з офіційних репозиторіїв
> sudo pacman -S --noconfirm wireshark-qt   # аналог -y, без підтвердження
> ```
> Пакети з офіційних репозиторіїв Arch (`core`, `extra`, `multilib`) покривають більшість базових інструментів. Для всього, чого там немає, існує **AUR (Arch User Repository)** — величезний архів community-скриптів збірки. AUR не встановлюється напряму через `pacman`, для цього використовують **AUR-хелпер**, найпоширеніший — `yay` або `paru`:
> ```bash
> yay -S bettercap-git      # встановлює з AUR так само зручно, як з офіційного репо
> ```
> AUR-пакети — це не бінарники, а PKGBUILD-скрипти збірки, що завантажують і компілюють вихідний код. Завжди переглядай PKGBUILD перед встановленням з AUR (`yay -Gp packagename`), бо це, по суті, довільний shell-код, що виконується з твоїми правами під час збірки.

### apt-get remove

Видаляє встановлений пакет.

```bash
# 🐧 Debian/Kali
apt-get remove wireshark
```

Це видаляє програму, але залишає її конфігураційні файли. Якщо хочеш видалити все, включно з конфігами:

```bash
apt-get purge wireshark
```

> **⚡ CachyOS (Arch):**
> ```bash
> sudo pacman -R wireshark-qt       # видалити пакет, залишити конфіги
> sudo pacman -Rns wireshark-qt     # видалити пакет + конфіги (-n) + залежності, що більше нікому не потрібні (-s) — аналог apt-get purge
> ```

---

### apt-get upgrade

Оновлює всі встановлені пакети до останніх версій.

```bash
# 🐧 Debian/Kali
apt-get upgrade
```

Корисно запускати періодично, щоб інструменти були актуальними. Завжди спочатку запускай `apt-get update`, щоб оновити список пакетів перед оновленням.

> **⚡ CachyOS (Arch):** оновлення системи — це той самий `pacman -Syu`, що й вище. На rolling-release дистрибутиві на кшталт CachyOS оновлення варто робити частіше (раз на кілька днів), а не рідко великими порціями — так менше шансів зловити конфлікт пакетів. Перед великим оновленням варто перевірити [Arch news](https://archlinux.org/news/) (або `informant`/`arch-audit`) на предмет ручних кроків (manual intervention), які іноді вимагаються при мажорних змінах у базових пакетах.

---

### apt-cache search

Шукає у локальній базі даних репозиторіїв пакети за ключовим словом. Корисно, коли ти приблизно знаєш, що шукаєш, але не знаєш точну назву пакета.

```bash
# 🐧 Debian/Kali
apt-cache search wifi
```

Повертає список пакетів, у назві або описі яких є "wifi". Далі ти обираєш те, що виглядає правильно, і встановлюєш за назвою.

```bash
apt-cache search wireless
apt-cache search password crack
```

> **⚡ CachyOS (Arch):**
> ```bash
> pacman -Ss wifi          # пошук в офіційних репозиторіях
> yay -Ss wifi              # пошук одразу і в офіційних репо, і в AUR
> pacman -Si wireshark-qt   # детальна інформація про конкретний пакет (аналог apt-cache show)
> ```

### git clone

Багато найкращих і новітніх хакерських інструментів не знаходяться в репозиторії — вони живуть на GitHub. `git clone` завантажує копію всього проєкту з GitHub напряму на твій комп'ютер.

```bash
git clone https://github.com/username/toolname
```

Це створює папку з назвою інструмента в поточній директорії. Більшість інструментів містять файл `README`, який пояснює, як їх встановити й запустити.

Загальний процес після клонування:

```bash
git clone https://github.com/example/tool
cd tool
```

Потім прочитай README з інструкціями по встановленню — зазвичай це щось на кшталт `pip install -r requirements.txt` або просто запуск Python-скрипта напряму.

> Багато найсвіжіших інструментів існують лише на GitHub. Навчання `git clone` на ранньому етапі означає, що ти не обмежений лише тим, що є в офіційних репозиторіях.

## Примітка про sources.list

Файл `/etc/apt/sources.list` містить URL-адреси всіх репозиторіїв, з яких система завантажує пакети. Його можна відкрити так:

```bash
cat /etc/apt/sources.list
```

Іноді в інтернеті знаходяться інструкції, які пропонують додати рядок у цей файл для доступу до стороннього репозиторію. Будь обережний. Офіційні репозиторії Kali підтримуються і перевіряються. Випадкові сторонні репозиторії — ні. Додавання неправильного джерела — простий спосіб встановити те, що ти зовсім не планував.

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

Матеріал вище описує `apt-get` — робочий, але дещо застарілий фронтенд. Ось що варто знати, якщо дивитися на керування пакетами очима людини, яка супроводжує Linux-сервери й робочі станції останнє десятиліття:

**`apt` замість `apt-get`/`apt-cache`.** З 2016 року (Debian 9+, і відповідно всі сучасні Kali) є уніфікована команда `apt`, яка об'єднує найпоширеніший функціонал `apt-get` і `apt-cache` в один інтерфейс з кольоровим виводом і прогрес-баром:

```bash
sudo apt update              # замість apt-get update
sudo apt install wireshark   # замість apt-get install
sudo apt remove wireshark    # замість apt-get remove
sudo apt search wifi         # замість apt-cache search
sudo apt list --upgradable   # що можна оновити
sudo apt autoremove          # прибрати "осиротілі" залежності, які більше нікому не потрібні
sudo apt full-upgrade        # upgrade, який дозволяє видаляти пакети, якщо це потрібно для розв'язання залежностей
```

`apt-get`/`apt-cache` нікуди не зникли (і залишаються стабільнішим вибором для скриптів, бо `apt` офіційно попереджає, що його CLI може змінюватися між версіями), але для інтерактивної роботи в терміналі сьогодні використовують саме `apt`.

**Порівняння філософій пакетних менеджерів (важливо розуміти, а не просто запам'ятати команди):**

| | Debian/Kali (`apt`, .deb) | Arch/CachyOS (`pacman`, .pkg.tar.zst) |
|---|---|---|
| Модель релізів | Стабільні релізи (Debian) / rolling з тестуванням (Kali) | Чистий rolling release |
| Версії пакетів | Часто "заморожені" — стабільні, але старіші | Завжди максимально свіжі |
| Джерело нових пакетів поза репо | PPA, сторонні `.deb`, `git clone` + збірка вручну | AUR — величезний, напівофіційний, community-контрольований шар |
| Ризик "часткового оновлення" | Низький — apt розв'язує залежності обережно, версії сумісні довше | Високий — треба завжди `-Syu` разом, ніколи не `-Sy` окремо |
| Типова причина проблем | Застарілі версії інструментів у стабільному репо | Рідкісні, але можливі breaking changes після оновлень (пом'якшується читанням Arch news) |

**Практичний висновок для security/pentest роботи:** якщо ти працюєш з Kali — тримайся `apt`/`apt-get`, це найбезпечніший і найбільш "протестований" шлях саме для набору security-тулзів, які там курують мейнтейнери Kali. Якщо ти будуєш власне робоче середовище на CachyOS/Arch (наприклад, заради продуктивності або новіших версій ядра й драйверів), знай, що `blackarch` — це репозиторій security-інструментів для Arch-подібних систем (аналог того, чим Kali є для Debian), який можна додати окремо, не переходячи на цілий інший дистрибутив:

```bash
# додавання репозиторію BlackArch до вже встановленого Arch/CachyOS
curl -O https://blackarch.org/strap.sh
chmod +x strap.sh
sudo ./strap.sh
```

Це дає доступ до ~2800+ security-інструментів через звичайний `pacman`, без потреби тримати окрему VM з Kali для кожної дрібної задачі — компроміс, який варто знати, навіть якщо для навчання за цим курсом Kali залишається правильним і найпростішим вибором.

## Довідка по командам

| Дія | 🐧 Debian/Kali | ⚡ CachyOS (Arch) |
|---|---|---|
| Оновити список пакетів | `apt-get update` | `sudo pacman -Sy` (краще одразу `-Syu`) |
| Встановити пакет | `apt-get install [name]` | `sudo pacman -S [name]` |
| Встановити без підтвердження | `apt-get install -y [name]` | `sudo pacman -S --noconfirm [name]` |
| Видалити пакет | `apt-get remove [name]` | `sudo pacman -R [name]` |
| Видалити разом із конфігами | `apt-get purge [name]` | `sudo pacman -Rns [name]` |
| Оновити всі пакети | `apt-get upgrade` | `sudo pacman -Syu` |
| Пошук пакета | `apt-cache search [keyword]` | `pacman -Ss [keyword]` |
| Встановити з community-репо (AUR) | PPA / сторонній `.deb` | `yay -S [name]` |
| Клонувати з GitHub | `git clone [url]` | `git clone [url]` |

---

## Практика

- Запусти `apt-get update`, щоб оновити список пакетів
- Використай `apt-cache search wifi` і подивись, що повернеться
- Вибери один інструмент із результатів і встанови його через `apt-get install`
- Знайди будь-який простий інструмент на GitHub і завантаж його на свій комп'ютер через `git clone`
