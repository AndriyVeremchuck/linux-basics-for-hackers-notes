# Linux Basics for Hackers
## Модуль 15 — Ядро Linux і завантажувані модулі ядра

---

## Про що цей модуль

Ядро — це серце операційної системи. Усе інше — твій термінал, твої програми, файлові системи — стоїть поверх нього. Цей модуль про те, як зрозуміти, що робить ядро, як перевіряти та змінювати його налаштування, і як модулі працюють як спосіб розширити функціональність ядра без перезавантаження.

---

## Що ядро робить насправді

Ядро стоїть між твоїм програмним забезпеченням і обладнанням. Коли програма хоче прочитати файл, відправити дані в мережу або намалювати щось на екрані, вона не говорить із обладнанням напряму — вона просить ядро, а ядро вже займається цим.

Саме тому ядро є найпривілейованішою частиною програмного забезпечення в системі. Воно працює в **kernel space**, який повністю відокремлений від **user space**, де виконуються твої програми. Процес у user space може робити лише те, що дозволяє ядро. Саме ядро таких обмежень не має — воно може отримувати доступ до будь-якої пам'яті, будь-якого обладнання, чого завгодно.

Саме тому це також така прицільна мішень. Код, який працює в ядрі, має абсолютну владу над машиною.

---

## Перевірка версії ядра

```bash
uname -a
```

Вивід:
```
Linux kali 6.1.0-kali9-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.27-1kali1 x86_64 GNU/Linux
```

Читання зліва направо:
- `Linux` — ОС
- `kali` — ім'я хоста
- `6.1.0-kali9-amd64` — версія ядра та архітектура
- `x86_64` — підтвердження, що це 64-розрядне ядро

Частина архітектури (`x86_64` vs `i686`) показує, чи це 64-бітне або 32-бітне ядро.

> **⚡ CachyOS:** там вивід виглядатиме інакше, наприклад `Linux hostname 6.11.x-cachyos x86_64 GNU/Linux` — замість `-kaliN` буде `-cachyos` (або `-cachyos-lto`/`-cachyos-bore` залежно від того, яке з кількох ядер CachyOS обрано — вона надає власні оптимізовані збірки ядра з різними планувальниками процесора). Це не помилка, а очікувана різниця: назва суфікса ядра просто показує, хто зібрав і пропатчив саме цей kernel-пакет.

## Завантажувані модулі ядра (LKMs)

Ядро не можна перекомпілювати і замінювати кожного разу, коли треба підтримати новий пристрій. Натомість воно підтримує **loadable kernel modules** — шматки коду ядра, які можна підключати й вивантажувати під час роботи системи, без перезавантаження.

Драйвери — найпоширеніший приклад. Коли ти вставляєш USB Wi‑Fi адаптер, ядро завантажує відповідний модуль драйвера, щоб спілкуватися з ним. Коли ти виймаєш його, модуль можна видалити. Саме ядро не змінюється — модуль просто розширює його тимчасово.

Оскільки модулі працюють у kernel space, вони мають ту ж абсолютну владу, що й ядро. Саме тому їх також використовують для приховування rootkit — шкідливого коду, вставленого як модуль, який може перехоплювати системні виклики, приховувати процеси, приховувати файли і робити все це на рівні, який ОС важко перевіряє.

---

## Перелік завантажених модулів

```bash
lsmod
```

Показує кожен модуль, який наразі завантажений в ядро:

```
Module                  Size  Used by
bluetooth             663552  2 btusb
snd_hda_intel         57344  3
usbcore              286720  5 btusb,xhci_hcd
```

Колонки такі:
- `Module` — назва модуля
- `Size` — скільки пам'яті він використовує
- `Used by` — інші модулі або процеси, від яких він залежить

Зазвичай ти побачиш десятки завантажених модулів. Більшість — це драйвери обладнання: звук, USB, дисплей, мережа.

---

## Отримання інформації про модуль

```bash
modinfo bluetooth
```

Вивід включає:
- `filename` — де знаходиться файл модуля на диску
- `description` — що він робить
- `author` — хто його написав
- `depends` — інші модулі, від яких він залежить
- `vermagic` — для якої версії ядра він скомпільований

Поле `depends` особливо корисне. Часто модулі залежать від інших модулів — їх треба завантажити спочатку. `modinfo` показує цей ланцюг.

---

## Завантаження та видалення модулів

**Додати модуль:**

```bash
modprobe bluetooth
```

`modprobe` — правильний інструмент для цього. На відміну від `insmod` (нижчого рівня), `modprobe` автоматично розв'язує і завантажує всі залежності, які потрібні модулю. Якщо `bluetooth` потребує два інші модулі, `modprobe` впорається з цим автоматично.

**Видалити модуль:**

```bash
modprobe -r bluetooth
```

Прапор `-r` видаляє модуль. Знову ж таки, `modprobe` обробляє залежності — він не видалить модуль, від якого ще щось залежить.

## `sysctl` — зміна параметрів ядра під час роботи

Ядро розкриває велику кількість параметрів через віртуальну файлову систему `/proc/sys`. Команда `sysctl` дозволяє читати й змінювати ці параметри під час роботи системи.

**Подивитися всі поточні параметри ядра:**

```bash
sysctl -a
```

Це довгий список. Щоб подивитися конкретний параметр:

```bash
sysctl net.ipv4.ip_forward
```

Вивід:
```
net.ipv4.ip_forward = 0
```

Цей параметр — IP forwarding — визначає, чи система буде пересилати мережеві пакети з одного інтерфейсу на інший. За замовчуванням вимкнено. Коли він вимкнений, машина отримує пакет, визначає, що він не адресований їй, і відкидає його.

**Увімкнути IP forwarding:**

```bash
sysctl -w net.ipv4.ip_forward=1
```

Прапор `-w` означає "write". Тепер ядро буде пересилати пакети між інтерфейсами. Це потрібно для setup'ів Man-in-the-Middle — машина має перебувати в центрі потоку трафіку, отримувати пакети, призначені комусь іншому, і пересилати їх далі.

**Зробити зміну sysctl постійною:**

Як і з змінними середовища, `sysctl -w` діє тільки до наступного перезавантаження. Щоб зробити її постійною, треба додати запис у `/etc/sysctl.conf`:

```
net.ipv4.ip_forward = 1
```

Потім застосувати без перезавантаження:

```bash
sysctl -p
```

**Будь обережний з `sysctl`.** Деякі налаштування керують фундаментальною поведінкою ядра. Зміна неправильного значення може викликати проблеми з мережею, нестабільність або ще гірше. Завжди знай, що саме робить параметр, перш ніж змінювати його.

## Файлова система `/proc`

Поряд з `sysctl` варто знати про `/proc` — це віртуальна файловка система, яка існує лише в пам'яті. Це ядро показує інформацію про себе та провиконувані процеси у вигляді файлів.

```bash
ls /proc
```

Ти побачиш числові директорії — по одній на кожен процес (число — PID). Також будуть файли на кшталт `cpuinfo`, `meminfo` і `version`, що показують апаратну інформацію та дані ядра.

```bash
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/version
```

Це не реальні файли на диску. Вони генеруються "на льоту" ядром кожного разу, коли їх читають. Це і є філософія "everything is a file" в її логічному завершенні — навіть динамічні дані ядра подаються як файли.

## Довідка по командам

| Команда | Що робить |
|---|---|
| `uname -a` | Показати повну версію ядра та архітектуру |
| `lsmod` | Показати всі поточно завантажені модулі ядра |
| `modinfo [name]` | Показати деталі про модуль |
| `modprobe [name]` | Завантажити модуль (і залежності) |
| `modprobe -r [name]` | Видалити модуль |
| `sysctl -a` | Показати всі параметри ядра |
| `sysctl [parameter]` | Показати конкретний параметр ядра |
| `sysctl -w [param=value]` | Змінити параметр ядра під час роботи |
| `sysctl -p` | Застосувати зміни з `/etc/sysctl.conf` |
| `cat /proc/cpuinfo` | Інформація про CPU від ядра |
| `cat /proc/meminfo` | Інформація про пам'ять від ядра |

---

## Практика

- Виконай `uname -a` і визнач версію ядра та чи це 32 або 64 бітне ядро
- Запусти `lsmod` і прокрути список — порахуй приблизно, скільки модулів завантажено
- Виконай `modinfo bluetooth` і знайди поле `depends` — подивися, від яких модулів він залежить
- Виконай `sysctl net.ipv4.ip_forward` і перевір поточне значення — поміркуй, що означає його зміна
