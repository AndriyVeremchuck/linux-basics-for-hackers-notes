# Linux Basics for Hackers
## Модуль 6 — Керування процесами

---

## Про що цей модуль

У будь-який момент твій комп'ютер запускає сотні речей одночасно — твій термінал, фонові сервіси, системні демони, речі, які ти навіть не запускав усвідомлено. Цей модуль про те, щоб бачити все це, розуміти, що є що, і вміти керувати цим. Це означає прискорення роботи, переміщення задач та завершення процесів, які зависли, з'їдають ресурси або просто заважають.

---

## Що таке процес?

Кожного разу, коли ти запускаєш програму, система створює для неї **процес**. Процес — це просто запущений екземпляр програми. Відкрити Firefox — це процес. Запустити команду в терміналі — це також процес. Навіть речі, які працюють тихо у фоні без вікна, теж є процесами.

Головне, що потрібно зрозуміти: кожен процес отримує унікальний номер під час запуску. Цей номер називається **PID — Process ID**. Саме так система (і ти) ідентифікує і звертається до конкретного процесу. Якщо хочеш зупинити щось, тобі потрібен його PID.

Є два типи процесів, які варто знати:

- **Foreground processes** — працюють на очах, прив'язані до твого терміналу. Якщо закрити термінал, вони завершаться.
- **Background processes** — працюють тихо "за лаштунками". Термінал залишається вільним, поки вони працюють.

---

## Як бачити, що працює

### ps

`ps` показує знімок процесів, що працюють прямо зараз. Сам по собі він показує лише процеси, прив'язані до поточного сеансу терміналу, що не дуже корисно. Натомість потрібно таке:

```bash
ps aux
```

Розбір прапорців:
- `a` — показати процеси всіх користувачів, а не лише твого
- `u` — показати користувача, який володіє процесом
- `x` — включити процеси, не прив'язані до термінала (фонові демони)

Вивід виглядає приблизно так:

```
USER       PID  %CPU  %MEM    VSZ   RSS  STAT  COMMAND
root         1   0.0   0.1  22548  1024  Ss    /sbin/init
kali      1023   0.3   1.2  54320  6200  S     bash
kali      1587   2.1   4.5 412300 22800  Sl    firefox
```

Стовпці, які важливі найбільше:

| Стовпчик | Що показує |
|---|---|
| USER | Хто володіє процесом |
| PID | ID процесу — саме його ти будеш використовувати для завершення |
| %CPU | Скільки CPU він використовує |
| %MEM | Скільки RAM він використовує |
| COMMAND | Яка програма фактично працює |

`ps aux` — це статичний знімок. Він показує стан речей у той момент, коли ти виконав команду, і зупиняється.

---

### top

`top` — це живий режим. Він оновлюється кожні кілька секунд і показує те, що працює зараз, сортування за використанням CPU за замовчуванням — тому те, що споживає найбільше ресурсів, стоїть зверху.

```bash
top
```

Корисні клавіші всередині `top`:

| Клавіша | Що робить |
|---|---|
| `k` | Завершити процес — попросить ввести PID |
| `M` | Сортувати за використанням пам'яті замість CPU |
| `P` | Сортувати за CPU (за замовчуванням) |
| `q` | Вийти |

Якщо твій комп'ютер раптово став повільним і ти не знаєш чому, відкрий `top` негайно. Жадібний процес буде на самому верху списку.

---

## Запуск процесів у фоновому режимі

За замовчуванням, коли ти запускаєш команду, вона завойовує твій термінал до завершення. Ти не можеш вводити нічого іншого, поки вона працює. Якщо ти запускаєш щось на кшталт браузера або довготривалого інструмента і хочеш повернути термінал, додай `&` наприкінці команди.

```bash
firefox &
```

Вивід:
```
[1] 2341
```

`[1]` — номер завдання. `2341` — PID. Firefox тепер працює у фоновому режимі, і твій термінал вільний.

---

## Переміщення процесів між переднім і фоновим режимами

Коли щось уже працює, його можна перемістити.

**Призупинити foreground процес** (поставити на паузу без завершення):
```bash
Ctrl + Z
```

**Відправити призупинений процес у фон** (залишити його працювати, але поза увагою):
```bash
bg
```

**Повернути фоновий процес у foreground:**
```bash
fg
```

Якщо запущено кілька фонових задач, `fg` поверне останню. Щоб повернути конкретну, використай номер завдання:

```bash
fg 2
```

Подивитись усі фонові задачі та їх номери:

```bash
jobs
```

---

## Завершення процесів

Коли треба зупинити щось, використовуй `kill` і PID.

```bash
kill 2341
```

Це надсилає ввічливий сигнал завершення — просить процес самостійно припинити роботу. Найчастіше це працює нормально.

Якщо процес завис або відмовляється зупинятися, примусово заверши його:

```bash
kill -9 2341
```

Прапорець `-9` надсилає сигнал **SIGKILL**, який процес не може ігнорувати, перехопити або відкласти. Він завершується негайно, без питань. Уяви звичайний `kill` як прохання людині піти, а `kill -9` — як фізичне видалення.

**Будь обережний з процесами, що належать root.** Якщо вбити системний процес, що належить root, не знаючи, що він робить, можна дестабілізувати або зламати систему. Завжди перевіряй стовпець COMMAND у `ps aux`, перш ніж вбивати щось, у чому не впевнений.

---

## Пошук PID без ps

Якщо ти вже знаєш назву процесу, тобі не треба прокручувати вивід `ps aux`. Використай `pgrep`:

```bash
pgrep firefox
```

Повертає лише PID. Чисто і швидко.

Або `pidof`:

```bash
pidof firefox
```

Робить те саме. Це просто питання переваги.

---

## Чому це важливо для хакерства

Коли ти потрапляєш на систему, однією з перших речей є виконання `ps aux` і перегляд того, що працює. Ти шукаєш:

- **Антивірус або захист кінцевих точок** — якщо збираєшся запускати експлойт або скинути файл, потрібно знати, що за тобою спостерігає. Знайти процес і вбити його (якщо є права) — поширений крок.
- **Цікаві сервіси** — бази даних, веб-сервери, внутрішні інструменти. Вони показують, для чого використовується машина і що варто атакувати.
- **Процеси інших користувачів** — якщо в систему увійшло кілька користувачів, їх процеси теж тут видно. Це корисна інформація.

`ps aux` — це інструмент recon так само, як і інструмент керування.

---

## Довідка по командам

| Команда | Що робить |
|---|---|
| `ps aux` | Знімок усіх процесів, що працюють |
| `top` | Живий перегляд процесів, сортування за ресурсами |
| `kill PID` | Ввічливо попросити процес зупинитися |
| `kill -9 PID` | Примусово зупинити процес негайно |
| `pgrep name` | Отримати PID процесу за назвою |
| `pidof name` | Те саме, альтернативний синтаксис |
| `jobs` | Показати всі фонові задачі поточного сеансу |
| `fg` | Повернути останню фонову задачу на передній план |
| `bg` | Відправити призупинену задачу у фон |
| `command &` | Запустити команду у фон відразу |
| `Ctrl + Z` | Призупинити активний foreground процес |
| `updatedb` | (з попереднього модуля) просто нагадаємо — потрібні права root |

---

## Примітка про сигнали

`kill` не просто вбиває речі — він надсилає **сигнали** процесам. `-9` (SIGKILL) — найбільш агресивний. Але є й інші, які варто знати пізніше:

| Сигнал | Номер | Що робить |
|---|---|---|
| SIGTERM | 15 | Ввічливий запит на завершення (за замовчуванням) |
| SIGKILL | 9 | Негайне примусове завершення |
| SIGHUP | 1 | Перезавантажити конфіг без перезапуску |

Найчастіше ти використовуватимеш 9 і 15. Інші виникають пізніше, коли мова йде про сервіси і демони.

## Practice

- Виконай `ps aux` і знайди процес свого термінала — запиши його PID
- Відкрий `top` і подивись, як він оновлюється. Знайди, який процес зараз найбільше навантажує CPU
- Виконай `leafpad &` (або будь-який текстовий редактор) у фоні, потім знайди його PID через `pgrep`, і заверши через `kill -9`
- Спробуй `Ctrl + Z` на активній команді, потім поверни її через `fg`

Найважливіше — відпрацювати послідовність "запустити → знайти PID → завершити процес" до автоматизму. Повтори це кілька разів.

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

`ps aux` і `top` — базові інструменти, і вони будуть на будь-якому сервері завжди, тому їх варто знати напам'ять. Але для щоденної інтерактивної роботи практично всі сучасні системні адміністратори користуються **`htop`**, а дедалі частіше — **`btop`**:

```bash
# 🐧 Debian/Kali
sudo apt install htop btop

# ⚡ CachyOS (Arch)
sudo pacman -S htop btop
```

**Чим `htop` кращий за `top`:**
- Кольоровий, інтерактивний інтерфейс — можна прокручувати список процесів, сортувати клавішами (F6), вбивати процес прямо з інтерфейсу (F9) без введення PID вручну
- Показує дерево процесів (`H`/`t`) — одразу видно, який процес породив який
- Показує використання кожного ядра CPU окремо, а не загальний відсоток

**`btop`** йде ще далі — графіки завантаження CPU/RAM/мережі/диска в реальному часі прямо в терміналі, миша працює для кліків по процесах, тема оформлення налаштовується. Це вже більше схоже на графічний диспетчер задач, ніж на класичний `top`.

**Практичний висновок:** `ps aux`/`top` — обов'язкова база (вони будуть навіть на мінімальному Docker-контейнері чи urgent-доступі по SSH без можливості щось встановити). Але якщо ти адмініструєш власний сервер чи робочу станцію постійно — постав `htop` або `btop` одразу, це суттєво пришвидшує діагностику "хто з'їдає ресурси" порівняно зі статичним виводом `top`.
