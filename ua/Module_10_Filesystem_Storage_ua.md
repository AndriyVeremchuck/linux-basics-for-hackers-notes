# Linux Basics for Hackers
## Модуль 10 — Файлова система та накопичувачі

---

## Про що цей модуль

У Linux відносини зі сховищами даних зовсім інші, ніж у Windows. Немає літер дисків, немає автоматичних спливаючих вікон при підключенні. Усе — це файл, кожен пристрій живе десь у дереві файлової системи, і якщо ти хочеш користуватися диском, його треба явно підключити. Цей модуль пояснює, як усе це працює.

---

## Усе — це файл

У Linux фраза "everything is a file" не просто приказка — це буквально те, як побудована система. Твій жорсткий диск не існує окремо від файлової системи. Він представлений як файл у `/dev`. Клавіатура — це файл. Мережева карта — це файл. Пристрої — це просто спеціальні файли, до яких ядро вміє звертатися.

Пристрої зберігання розташовані в `/dev` і називаються так:

| Пристрій | Що це таке |
|---|---|
| `/dev/sda` | Перший жорсткий диск |
| `/dev/sdb` | Другий жорсткий диск |
| `/dev/sdc` | Третій жорсткий диск (або USB) |
| `/dev/sda1` | Перша розділ на першому диску |
| `/dev/sda2` | Друга розділ на першому диску |
| `/dev/sr0` | CD/DVD-привід |

`sd` означає SCSI disk — назва походить від старого стандарту інтерфейсу, але вона використовується також для сучасних SATA і USB-дисків. Літера після `sd` — порядок диска (`a` = перший, `b` = другий). Число після цього — номер розділу.

Тобто `/dev/sdb3` означає: другий диск, третій розділ.

## Монтування — як Linux підключає диски

У Windows, коли вставляєш USB, він автоматично отримує літеру типу `D:`. Linux так не робить. Ти повинен **монтувати** диск сам.

Монтування означає сказати Linux: "прикріпи цей пристрій до цієї папки в дереві". Після монтування ти отримуєш доступ до диска, переходячи в цю папку. Папка, до якої прив’язаний пристрій, називається **точка монтування**.

```
/
└── mnt/
    └── usb/    ← твій USB-диск з'явиться тут після монтування
```

Стандартні місця для точок монтування — `/mnt` (для тимчасового ручного монтування) і `/media` (де система автоматично монтує USB, наприклад у графічному середовищі).

**Щоб змонтувати диск:**

```bash
mount /dev/sdb1 /mnt/usb
```

Це прикріплює перший розділ другого диска до папки `/mnt/usb`. Після цього, зайшовши до `/mnt/usb`, ти побачиш файли на цьому диску.

Папка має вже існувати до монтування:

```bash
mkdir /mnt/usb
mount /dev/sdb1 /mnt/usb
```

**Щоб відмонтувати:**

```bash
umount /mnt/usb
```

Зверни увагу на написання — це `umount`, а не `unmount`. Завжди відмонтовуй перед фізичним вийманням диска. Якщо система ще пише дані, а ти виймаєш його різко, можна пошкодити файлову систему.

---

## `fdisk` — бачити, які диски є

`fdisk -l` показує всі диски та розділи, підключені до системи. Потребує root.

```bash
fdisk -l
```

Вивід виглядає приблизно так:

```
Disk /dev/sda: 500 GB, 500107862016 bytes
Device     Boot    Start      End  Sectors  Size  Type
/dev/sda1  *        2048  1026047  1024000  500M  EFI System
/dev/sda2        1026048 97654784 96628737 46.1G  Linux filesystem

Disk /dev/sdb: 16 GB, 16013942784 bytes
Device     Boot  Start     End  Sectors  Size  Type
/dev/sdb1  *      2048 31252479 31250432 14.9G  Microsoft basic data
```

З цього можна побачити: підключено два диски, які розділи є в кожному, їх розмір і тип файлової системи. Це перший крок, коли ти маєш справу з невідомою машиною — треба зрозуміти, які накопичувачі приєднані.

---

## `df` — скільки місця залишилося

`df` означає "disk free". Вона показує, скільки місця використано і скільки доступно на кожній змонтованій файловій системі.

```bash
df -h
```

Прапор `-h` означає "human-readable" — показує розміри в ГБ і МБ замість сирих байтів.

Вивід:

```
Filesystem      Size  Used Avail Use%  Mounted on
/dev/sda2        46G   12G   32G  27%  /
/dev/sdb1        15G  8.1G  6.9G  54%  /mnt/usb
tmpfs           2.0G  1.2M  2.0G   1%  /run
```

Колонка `Use%` показує, які розділи майже заповнені. Записи `tmpfs` — це віртуальні файлові системи в RAM, не реальний диск.

---

## `/etc/fstab` — постійна конфігурація монтування

Коли ти монтуєш щось через `mount`, це тимчасово. Після перезавантаження диск більше не буде змонтований. Щоб зробити монтування постійним — щоб він автоматично монтувався під час завантаження — треба додати запис у `/etc/fstab`.

```bash
cat /etc/fstab
```

Кожен рядок у fstab описує одну файлову систему для монтування:

```
# device          mountpoint    fstype   options    dump  pass
/dev/sda1         /             ext4     defaults    0     1
/dev/sda2         /home         ext4     defaults    0     2
UUID=1234-ABCD    /mnt/data     ntfs     defaults    0     0
```

З погляду recon, `/etc/fstab` розповідає дуже багато про цільову систему. Там видно кожен диск, який монтується при завантаженні — включно з мережевими каталогами (NFS, SMB), зашифрованими томами та зовнішніми дисками. Сховані або незвичайні записи тут можуть вказати на цікаві речі для перевірки.

---

## `fsck` — перевірка та ремонт дисків

`fsck` означає "filesystem check". Вона перевіряє диск на помилки і може спробувати їх виправити.

```bash
fsck /dev/sdb1
```

**Критичне правило: ніколи не запускай `fsck` на змонтованій файловій системі.** Якщо диск змонтований і використовується, `fsck` може зробити пошкодження гіршим, а не кращим. Завжди відмонтовуй спочатку:

```bash
umount /dev/sdb1
fsck /dev/sdb1
```

Якщо перевіряєш корневий розділ (`/`), відмонтувати його під час роботи системи неможливо — треба завантажитися з live USB і запускати `fsck` звідти.

---

## Типи файлових систем

Під час форматування розділу ти обираєш тип файлової системи. У різних ОС використовуються різні формати. Це важливо, коли монтуєш диски від інших систем.

| Файлова система | Де її бачиш |
|---|---|
| ext4 | Стандартна Linux-файлова система |
| ext3 / ext2 | Старі Linux-файлові системи |
| NTFS | Windows-диски |
| FAT32 / exFAT | USB-диски, SD-карти (крос-платформенно) |
| XFS | Високопродуктивний Linux, часто на серверах |

Коли монтуєш диск не від Linux, іноді потрібно явно вказати тип:

```bash
mount -t ntfs /dev/sdb1 /mnt/windows
```

Linux може читати NTFS-диски нормально. Запис на них теж працює, але історично мав деякі нюанси — варто це знати.

---

## Монтування USB-диска — повний процес

Це повний маршрут від вставки до доступу до файлів:

```bash
# 1. Подивитися, що щойно підключили
fdisk -l

# 2. Створити точку монтування, якщо її немає
mkdir /mnt/usb

# 3. Змонтувати розділ
mount /dev/sdb1 /mnt/usb

# 4. Перевірити, що все працює
ls /mnt/usb

# 5. Робимо все, що треба

# 6. Відмонтовуємо, коли закінчили
umount /mnt/usb
```

## Довідка по командам

| Команда | Що робить |
|---|---|
| `fdisk -l` | Показати всі диски та розділи |
| `mount /dev/sdb1 /mnt/point` | Змонтувати розділ до папки |
| `mount -t ntfs /dev/sdb1 /mnt/point` | Змонтувати з вказанням типу файлової системи |
| `umount /mnt/point` | Безпечно відмонтувати диск |
| `df -h` | Показати використання дискового простору (людською мовою) |
| `fsck /dev/sdb1` | Перевірити й відремонтувати файлову систему (спочатку відмонтувати) |
| `cat /etc/fstab` | Показати постійну конфігурацію монтування |
| `mkdir /mnt/point` | Створити папку для точки монтування |
| `lsblk` | Чистий огляд дисків і розділів |

Одна додаткова команда варта згадки: `lsblk` дає чистіший вигляд, ніж `fdisk -l`, коли хочеш просто подивитися структуру дисків:

```bash
lsblk
```

Вивід:
```
NAME   MAJ:MIN  SIZE  TYPE  MOUNTPOINT
sda    8:0      500G  disk
├─sda1 8:1      500M  part  /boot
└─sda2 8:2      499G  part  /
sdb    8:16      16G  disk
└─sdb1 8:17     16G  part  /mnt/usb
```

Читати простіше, ніж сирий `fdisk`.

---

## Практика

- Виконай `fdisk -l` і визнач усі диски та розділи, підключені до твоєї VM
- Виконай `df -h` і знайди розділ, який найближчий до заповнення
- Створи `/mnt/test` через `mkdir`, підключи USB-диск (або додай віртуальний диск у VirtualBox), знайди його назву пристрою через `fdisk -l`, і змонтуй його в `/mnt/test`
- Після монтування виконай `ls /mnt/test`, щоб підтвердити, що все працює, потім `umount /mnt/test` в кінці
- Прочитай `/etc/fstab` і зрозумій, що робить кожен рядок

## 🔄 Сучасний погляд (нотатки з практики системного адміністрування)

**Аналіз використання диска: `du`/`df` → `ncdu`/`duf`.** Класичні `du -sh */` та `df -h` дають цифри, але не дають наочності — щоб знайти "що саме з'їдає диск", доводиться рекурсивно перебирати папки вручну. Сучасний інструмент **`ncdu`** (NCurses Disk Usage) сканує дерево один раз і дає інтерактивний список папок, відсортований за розміром, з навігацією стрілками — знайти "що займає 40 ГБ" займає секунди замість хвилин ручного `du`:

```bash
# 🐧 Debian/Kali
sudo apt install ncdu duf

# ⚡ CachyOS (Arch)
sudo pacman -S ncdu duf

ncdu /                 # інтерактивний аналіз використання диска від кореня
duf                     # сучасна, кольорова заміна df -h з наочними прогрес-барами
```

**Файлові системи: чому btrfs/ZFS змінюють правила гри.** Курс тут описує класичний підхід ext4 + `fdisk`/`fsck` — це надійна, перевірена десятиліттями база, яку варто знати завжди. Але сучасні файлові системи з copy-on-write (**btrfs**, **ZFS**) дають можливості, недоступні в ext4 в принципі, а не просто "зручніші команди":

- **Знімки (snapshots) миттєво й безкоштовно** — `btrfs subvolume snapshot` створює точку відновлення за мілісекунди, без копіювання даних (copy-on-write означає, що дані фізично дублюються лише коли змінюються). Це дозволяє відкотити всю систему після невдалого оновлення пакетів одним `btrfs snapshot rollback` — саме тому CachyOS за замовчуванням встановлюється на btrfs зі знімками, інтегрованими у `pacman` через хуки (`snapper`/`snap-pac`).
- **Вбудована прозора компресія** (`compress=zstd` в опціях монтування — той самий `zstd`, що й у модулі про архівування, але застосований на льоту до кожного файлу файлової системи).
- **Контрольні суми даних (checksums)** — btrfs і ZFS виявляють тихе пошкодження даних (silent data corruption/bit rot), чого ext4 в принципі не робить на рівні файлової системи.

**Практичний висновок:** ext4 + `fdisk` + `fsck` — правильна база для навчання і досі домінуючий вибір на серверах, де важлива максимальна передбачуваність і сумісність. Але якщо ти адмініструєш власну робочу станцію чи новий сервер сьогодні (зокрема на CachyOS, де btrfs — стандарт із коробки), варто розуміти снепшоти й прозору компресію btrfs як частину сучасного інструментарію системного інженера, а не лише "ще один тип диска" в `fdisk -l`.
