# Linux Basics for Hackers
## Модуль 13 — Безпека та анонімність

---

## Про що цей модуль

Усе, що ти робиш в інтернеті, залишає слід. Кожен сайт, до якого заходиш, кожне з'єднання, що встановлює твоя машина — твоя реальна IP-адреса прив'язана до нього. Цей модуль про те, як це відстеження працює і як інструменти на кшталт Tor, проксі, VPN і proxychains зменшують твоє розкриття. Це важливо і для захисту себе, і для розуміння інфраструктури, на якій базуються приватні люди (і атакуючі).

---

## Чому IP-адреса має значення

Твою IP-адресу тобі назначає провайдер. Кожне з'єднання, яке ти встановлюєш із будь-яким сервером в інтернеті, несе її з собою. Сервер, до якого ти підключаєшся, бачить її. Твій ISP також бачить, з чим ти підключаєшся. Будь-яка мережа, до якої ти підключений, бачить твій трафік.

Це проблема, яку вирішують інструменти анонімності — вони ставлять щось між тобою і ціллю так, що ціль бачить іншу IP-адресу, а не твою.

---

## Проксі

Проксі — це сервер, який стоїть між тобою та ціллю. Замість того, щоб підключатися напряму до сайту, ти підключаєшся до проксі, а проксі підключається до сайту від твого імені. Сайт бачить IP проксі, а не твій.

```
Ти → Проксі → Сайт
```

Сайт записує IP проксі. Твій провайдер бачить, що ти під'єднався до проксі, але не бачить, що саме ти там робив.

Одиночний проксі — найслабша форма анонімності. Сам проксі знає твою реальну IP і знає, куди ти йдеш. Якщо на нього подають subpoena або він веде логи, твою активність можна простежити.

**Безкоштовні проксі майже завжди погана ідея** для чого-небудь чутливого. Багато з них спеціально створені для збору трафіку — honeypots, що зберігають усі дані, що проходять через них. Якщо ти не довіряєш випадковому незнайомцю нести твою пошту, не довіряй випадковому безкоштовному проксі.

---

## Tor — лукова маршрутизація

Tor маршрутизує твій трафік через ланцюжок із трьох серверів, які називають **nodes** або **relays**, кожен з яких працює на волонтерських машинах по всьому світу. Кожен relay знає тільки попередній і наступний крок — жоден окремий relay не знає одночасно, хто ти і куди йдеш.

```
Ти → Entry Node → Middle Node → Exit Node → Сайт
```

Шифрування працює шарами — як цибуля. Твій трафік загортається в три шари шифрування. Кожен вузол знімає один шар, щоб зрозуміти, куди відправити далі, але не може прочитати реальний вміст або побачити повний маршрут.

Сайт бачить IP exit node, а не твій. Entry node знає твою IP, але не знає пункт призначення. Middle node знає нікого.

**Як користуватися в Kali:**

```bash
# 🐧 Debian/Kali
apt install tor
service tor start
```

> **⚡ CachyOS (Arch):** `sudo pacman -S tor` + `sudo systemctl start tor` (немає команди `service`). Конфіг та шлях `/etc/tor/torrc` однакові на обох дистрибутивах.

Або завантаж Tor Browser — це попередньо налаштований Firefox, який автоматично маршрутизує весь трафік через Tor.

**Компроміс:** Tor повільний. Три переходи через волонтерські сервери по всьому світу додають суттєву затримку. Він не підходить для високошвидкісних активностей або будь-чого, що критично до часу. Також це не магічний щит — погана операційна безпека на рівні додатка (наприклад, вхід у особистий акаунт) скасовує його повністю.

## Proxychains — примусове маршрутизування інструментів через проксі

Tor і VPN захищають трафік браузера. Але якщо ти запускаєш термінальний інструмент — `nmap`, `curl`, кастомний скрипт — його трафік йде напряму, якщо ти не направиш його через щось.

`proxychains` — це інструмент, який перехоплює мережеві виклики з будь-якої програми і примусово направляє їх через заданий ланцюжок проксі. Ти ставиш його перед будь-якою командою, і трафік буде редіректитися.

```bash
proxychains nmap -sT 192.168.1.1
```

Тепер трафік `nmap` пішов через твій ланцюжок проксі перед тим, як дійти до цілі.

**Конфігураційний файл:**

```bash
nano /etc/proxychains.conf
```

Унизу ти знайдеш список проксі. Додавай їх у такому форматі:

```
socks5  127.0.0.1  9050    ← це локальний порт Tor
socks4  10.0.0.1   1080
http    203.0.113.5  3128
```

Якщо додати `127.0.0.1 9050` (локальний порт Tor за замовчуванням) і мати запущений Tor, proxychains буде маршрутизувати все через Tor. Разом це означає, що навіть твої термінальні інструменти йдуть через Tor-мережу.

**Два режими, які варто знати в конфігурації:**

- `strict_chain` — трафік має проходити через кожен проксі по порядку; якщо один з них впав, з'єднання не встановиться
- `dynamic_chain` — пропускає мертві проксі автоматично і використовує те, що доступне

Для більшості випадків `dynamic_chain` практичніший.

## VPN

VPN (Virtual Private Network) створює зашифрований тунель між тобою та VPN-сервером. Увесь твій трафік проходить через цей тунель, зашифрований, перед тим як вийти в інтернет. Твій ISP бачить тільки те, що ти підключився до VPN, але не що саме робиш.

```
Ти → [зашифрований тунель] → VPN Сервер → Інтернет
```

Порівняно з Tor:
- VPN швидші
- залучений тільки один сервер — провайдер VPN може бачити твій трафік і логи, якщо захоче
- провайдер VPN знає твою реальну IP

Репутаційні платні VPN з перевіреною політикою без логів — стандартний вибір. Ключова фраза — "no-log policy" — тобі потрібен провайдер, який доведено не зберігає записів про те, що ти робиш.

**VPN + Tor разом** — підхід, який іноді використовують, щоб максимально накладати шари:

```
Ти → VPN → Tor Network → Сайт
```

Твій ISP бачить VPN-трафік. Провайдер VPN бачить, що ти підключився до Tor, але не бачить пункт призначення. Exit node Tor не знає, хто ти. Сайт бачить exit node Tor.

Компроміс — ще більша затримка, ніж у Tor сам по собі.

## Шифровані комунікації

Анонімізація мережевого трафіку — одна сторона. І самі дані також важливі.

**ProtonMail** — це сервіс електронної пошти, де листи шифруються end-to-end. Повідомлення між користувачами ProtonMail шифруються таким чином, що сам ProtonMail їх не може прочитати. Навіть за судовим наказом нема чого передавати, бо ключі існують тільки на пристрої користувача.

Для загального обміну повідомленнями **Signal** працює за тим самим принципом — end-to-end encryption за замовчуванням, мінімальна метадані збережені.

Це стандартні інструменти для журналістів, активістів, адвокатів і будь-кого, хто працює з чутливою інформацією. Використання зашифрованого зв'язку не є самою по собі підозрілою річчю — це базова операційна гігієна.

---

## Що насправді руйнує анонімність

Інструменти хороші лише настільки, наскільки ти їх використовуєш. Більшість збоїв в анонімності виникають не на технічному, а на людському рівні:

- Вхід у особистий акаунт (Google, соціальні мережі) через Tor — сам акаунт ідентифікує тебе незалежно від IP
- Повторне використання імен користувачів для анонімної та неанонімної активності
- Browser fingerprinting — браузер витікає інформацію про твою ОС, роздільну здатність, встановлені шрифти, часовий пояс тощо навіть без cookies
- Метадані в файлах — документи та фото часто містять вбудовані дані про пристрій, який їх створив
- Довіра до безкоштовних або невідомих проксі для чутливого трафіку

Анонімність — це практика, а не просто інструмент, який встановив.

## Довідка по командам

| Команда | Що робить | ⚡ CachyOS |
|---|---|---|
| `service tor start` | Запустити сервіс Tor | `systemctl start tor` |
| `proxychains [command]` | Запускати будь-яку команду через ланцюжок проксі | те саме |
| `nano /etc/proxychains.conf` | Редагувати конфіг proxychains | той самий шлях |
| `curl ifconfig.me` | Перевірити, яку IP-адресу бачить інтернет | те саме |
| `proxychains curl ifconfig.me` | Перевірити свою "зовнішню" IP через proxychains |

---

## Практика

- Встанови і запусти Tor, а потім виконай `proxychains curl ifconfig.me` — IP, яке повернеться, не повинно бути твоєю реальною адресою
- Відкрий `/etc/proxychains.conf` і подивися на конфіг — додай локальний порт Tor (`socks5 127.0.0.1 9050`) до списку проксі
- Відвідай сайт "what is my IP" напряму, потім через Tor Browser — порівняй два IP
- Подивись на ProtonMail, якщо у тебе його ще немає — він безкоштовний і вартий використання для чогось чутливого
