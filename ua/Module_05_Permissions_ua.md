# Linux Basics for Hackers
## Модуль 5 — Права доступу та привілеї

---

## Про що цей модуль

Linux — багатокористувацька система. На одному комп'ютері може бути кілька облікових записів, і не всі повинні мати доступ до читання, зміни або запуску всього. Права доступу — це спосіб, яким Linux це забезпечує. Цей модуль пояснює, як читати права доступу, змінювати їх і розуміти, де вони стають проблемою безпеки.

---

## Як працюють права доступу

Кожен файл і папка в Linux має три групи прав доступу:

- **Owner** — користувач, який створив файл
- **Group** — набір користувачів, які мають спільний доступ
- **Others** — усі інші користувачі системи

Кожна з цих груп може мати три типи дозволів:

| Дозвіл | Символ | Що означає |
|---|---|---|
| Read | `r` | Можна переглядати вміст файлу |
| Write | `w` | Можна змінювати або видаляти файл |
| Execute | `x` | Можна запускати файл як програму |

Коли ти виконуєш `ls -l`, перший стовпець показує права доступу для кожного файлу:

```bash
ls -l
```

Приклад виводу:
```
-rwxr-xr--  1  kali  kali  4096  Jan 1  file.sh
```

Цей рядок символів на початку — блок прав. Розбір:

```
- rwx r-x r--
│  │   │   │
│  │   │   └── Others:  тільки читання
│  │   └────── Group:   читання + виконання
│  └────────── Owner:   читання + запис + виконання
└───────────── Тип файлу: - означає звичайний файл, d — каталог
```

Якщо ти завантажив хакерський інструмент і він відмовляється запускатися, зазвичай це тому, що біт виконання не встановлений.

---

## chmod — зміна прав доступу

`chmod` означає "change mode". Це спосіб, яким ти задаєш, хто що може робити з файлом.

Існує два способи використання: числовий і символічний.

### Числовий метод

Кожен дозвіл має числове значення:

| Дозвіл | Значення |
|---|---|
| Read (r) | 4 |
| Write (w) | 2 |
| Execute (x) | 1 |

Ти складаєш їх, щоб отримати права для кожної групи. Потім записуєш три цифри — по одній для власника, групи та інших.

| Число | Розрахунок | Права |
|---|---|---|
| 7 | 4+2+1 | Читання + Запис + Виконання |
| 6 | 4+2 | Читання + Запис |
| 5 | 4+1 | Читання + Виконання |
| 4 | 4 | Лише читання |
| 0 | 0 | Без прав |

Приклади:

```bash
chmod 755 script.sh
```

Власник отримує 7 (читання+запис+виконання). Група отримує 5 (читання+виконання). Інші отримують 5 (читання+виконання). Це стандартні права для скрипта, який хочеться запускати, але не дозволяти іншим змінювати.

```bash
chmod 644 notes.txt
```

Власник отримує 6 (читання+запис). Група отримує 4 (читання). Інші отримують 4 (читання). Стандарт для файлу, який інші можуть читати, але лише ти можеш редагувати.

```bash
chmod 777 file.sh
```

Усі отримують повний доступ — читання, запис і виконання. Легко набрати, але майже ніколи не правильне рішення. Це означає, що будь-хто в системі може змінювати або запускати файл, що є проблемою безпеки.

### Символічний метод

Замість чисел використовуються літери для вказівки змін:

```bash
chmod +x script.sh
```

Додає дозвіл на виконання всім.

```bash
chmod u+x script.sh
```

Додає виконання тільки власнику (`u` = user/owner).

```bash
chmod g-w file.txt
```

Видаляє дозвіл на запис для групи.

Літери: `u` = власник, `g` = група, `o` = інші, `a` = всі три.

## chown — зміна власника

`chown` означає "change owner". Це перевизначає, хто володіє файлом.

```bash
chown kali file.txt
```

Змінює власника на користувача `kali`.

```bash
chown kali:kali file.txt
```

Змінює і власника, і групу на `kali`.

```bash
chown -R kali /home/kali/tools
```

Прапорець `-R` застосовує зміну рекурсивно — змінює власника папки та всього, що в ній знаходиться.

Для зміни власності файлів, якими ти не володієш, потрібні права root.

---

## SUID — важливий біт

SUID означає "Set User ID". Це спеціальний біт дозволу, який змінює спосіб виконання файлу.

Зазвичай, коли ти запускаєш програму, вона виконується з твоїми правами. Якщо біт SUID встановлений на файлі, що належить root, програма виконується з правами root — навіть якщо ти звичайний користувач.

У рядку прав SUID відображається як `s` там, де мав би бути біт виконання власника:

```
-rwsr-xr-x   root   root   /usr/bin/passwd
```

Ця `s` у полі власника означає, що SUID встановлено. Команда `passwd` потребує SUID, бо їй потрібно записати до `/etc/shadow` (файл, що належить root), коли будь-який користувач змінює свій пароль.

SUID законний, якщо використовується навмисно. Проблема в тому, що файли можуть мати SUID помилково, або погано написані SUID-програми можуть бути використані для виконання непотрібних дій.

**Ось де починається підвищення привілеїв.** Підвищення привілеїв — це процес переходу від обмеженого користувача до root через вразливості в правах. Пошук неправильно налаштованого бінарного файлу SUID — один із класичних способів це зробити.

Щоб знайти всі файли в системі з встановленим бітом SUID:

```bash
find / -perm -u=s -type f 2>/dev/null
```

Розбір:
- `find /` — шукати від кореня
- `-perm -u=s` — знайти файли з бітами SUID
- `-type f` — лише файли, не каталоги
- `2>/dev/null` — приховати помилки прав доступу, щоб вивід був чистим

Запусти це на будь-якій Linux-системі і ознайомся з результатами. Будь-який файл там, який має відому вразливість або неправильну конфігурацію, може бути потенційним шляхом підвищення привілеїв.

---

## Коротко про підвищення привілеїв

Суть розуміння прав полягає в тому, що системи дуже часто компрометуються на рівні звичайного користувача. Зловмисник потрапляє як користувач з низькими привілеями, а потім шукає способи отримати root. Цей процес і називається privilege escalation.

Неправильні налаштування прав — один із найпоширеніших векторів атаки: SUID-бінарники, які не повинні мати SUID, файли, доступні для запису не тим користувачам, скрипти, що належать root, але доступні для редагування всім. Знання того, як працюють права, дозволяє помічати ці помилки — незалежно від того, атакуєш ти чи захищаєтьсяш.

## Довідка по командам

| Команда | Що робить | Приклад |
|---|---|---|
| `ls -l` | Показує права для файлів | `ls -l` |
| `chmod 755 file` | Встановлює права числово | `chmod 755 script.sh` |
| `chmod +x file` | Додає виконання для всіх | `chmod +x tool.py` |
| `chmod u+x file` | Додає виконання лише власнику | `chmod u+x run.sh` |
| `chown user file` | Змінює власника файлу | `chown kali file.txt` |
| `chown user:group file` | Змінює власника і групу | `chown kali:kali file` |
| `chown -R user dir` | Рекурсивна зміна власності | `chown -R kali /tools` |
| `find / -perm -u=s -type f 2>/dev/null` | Знаходить усі файли SUID | — |

## Практика

- Створи файл через `touch test.txt`, потім виконай `ls -l`, щоб прочитати значення прав за замовчуванням
- Використай `chmod 600 test.txt` — це дає тобі лише читання й запис, іншим — нічого. Перевір це через `ls -l`
- Створи простий скрипт, спробуй його запустити, побачиш помилку, потім використай `chmod +x` і запусти його знову
- Запусти команду `find` вище, щоб побачити всі SUID-файли в системі — ознайомся з результатами
